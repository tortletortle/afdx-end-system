## 1. 关闭既有冲突

### C-001 IC 丢帧后 PSN 是否推进 → **可关闭（支持现实现）**

**§3.2.6.2.1 原文**：

> The Integrity Checking tests each frame for a sequence number in the interval:
> **[PSN"+"1, PSN"+"2]**
> Where Previous Sequence Number (PSN) is the sequence number of the previous frame **received (but not necessarily forwarded)** on this VL.
> The operator "+" takes the wrap-around of Sequence Numbers into account. So, for example if PSN = 254 then PSN"+"1 = 255 and PSN"+"2 = 1.

特例（**应判为有效**）：

> • The Received Sequence Number (RSN) is equal to 0
> • The frame is the first frame received after any reset of the receiving ES
> Frames that do not meet these criteria are discarded.

另：**IC 应可按 VL 通过配置表禁用**；禁用后接受 A/B 两网全部帧。

**"received (but not necessarily forwarded)" 的两种读法**：

- (a) 每一个到达 IC 的帧都更新 PSN，**包括被 IC 丢弃的**；
- (b) 只有通过 IC 的帧更新 PSN，"not forwarded" 指**通过 IC 但被 RM 判为冗余而未上交分区**的帧。

**采用 (b)**，依据是规范自己的 COMMENTARY：

> This function increases integrity robustness. e.g.: by **eliminating stuck frames or single abnormal frames and reducing the impact of a babbling switch**.

若按 (a)，一个 babbling switch 注入 `SN = PSN+50` 的伪帧会把 PSN 拖走，随后的合法帧全部落到窗口外被拒——与"降低 babbling switch 影响"的立法意图直接矛盾。

**工程对照**：`rtl/rx/rx_ic.v` 第 2–3 行注释「a rejected frame never changes PSN」，即读法 (b)，**与本结论一致，无需改动**。窗口计算 `exp1/exp2`（含 254/255 回绕）与原文示例一致。

> 结论：**C-001 由"未决"改为"已关闭（按读法 b）"**，依据 L158 §3.2.6.2.1 及其 COMMENTARY。读法歧义本身记录在案。

### C-002 RM skew / timeout / 同拍仲裁 → **部分关闭**

**§3.2.6.2.2 原文要点**：

| 条文 | 内容 |
|---|---|
| SkewMax 定义 | 两个冗余帧**接收时刻**之间的最大时间；取决于网络拓扑（经过的交换机数），**由系统集成方按 VL 以 ms 配置给出** |
| 判据来源 | **RM 算法只能以帧的 RSN 作为接受/拒绝依据**；完整性检查是独立任务，即使不用冗余也要做 |
| 首达优先 | RM 激活时**交付先收到的那一份**（"First Win"）；发送 ES / 接收 ES / 交换机的任何复位都不应破坏该性质 |
| 复位假设 | COMMENTARY：**硬件复位时间假定大于 SkewMax**，以防复位前后帧互相干扰 |
| 顺序 | 每 VL 应保证帧按 **RSN 递增顺序**转发，复位与偶发丢帧下同样适用 |
| 超时行为 | **SkewMax 超出后，RM 接受下一帧，不论其 SN 为何** |
| 重排 | **只转发顺序内的帧，但不要求重排序**（后果是某些情况下会丢帧） |
| 可配置性 | RM 功能应可配置；每 VL 可选"冗余 VL 交付其一 / 冗余 VL 两份都交 / 非冗余 VL" |

**仍未规定、属实现自由度**（C-002 保留部分）：
同拍到达（A/B 同时）的仲裁、长期等待上界、RM 内部状态的具体组织。这几项继续按 `rx_rm` 微架构参数化 + 测试矩阵自证。

> 结论：**C-002 由"未决"改为"部分关闭"**，SkewMax 语义/首达/递增顺序/超时后无条件接受四条已有规范原文。

## 2. 其他可直接替换二手依据的条款

### 2.1 抖动上界 §3.2.4.3 — **500 μs 硬判据的规范原文**

> In transmission, the maximum allowed jitter on each VL at the output of the end-system should comply with **both** of the following formulas:
>
> max_jitter ≤ 40 μs + ( Σ_{i ∈ set of VLs} (20 + Lmax_i) × 8 ) / Nbw
> max_jitter ≤ 500 μs
>
> Note: max_jitter 单位 μs；Nbw 为介质带宽（bit/s）；Lmax 单位 octet；**40 μs 是典型的最小固定技术抖动**。
> …In all cases, the jitter is bounded at 500 μs to limit the impact on determinism for the whole network.

**意义**：本项目 T05b/T05bg 的 500 μs 硬判据、以及 D10「发送起始错相」的合规线，**此前依据是 L001/L064/L067 三篇二手文献**，现在可直接引用规范条款。
**注意公式第一式本项目此前未使用**——40 μs + Σ(20+Lmax)×8/Nbw 是随 VL 数与帧长增长的另一条上界，满配 128 VL 时它可能比 500 μs 更紧，**需要用 `tools/bag_model.py` 复算后决定是否补入判据**。

传输延迟上界（同节）：`MAX_Latency_i ≤ BAG_i + Max_jitter + Technological_Latency_in_transmission`。

### 2.2 BAG §3.2.2

> BAG = 2^k [in ms]，k 为 0…7 的整数，即 1 ms … 128 ms。
> 最大可用带宽 = Lmax / BAG（KB/s）。ES 收发都应支持最大 1518 字节的 VL 帧。
> 每 VL 的 BAG 值来自 ES 配置表。

### 2.3 SN §3.2.6.1

> 每 VL 每帧加一个**一个八位组**的序列号，范围 0–255。
> 每 VL 初始置 0；发送 ES 复位后总是回到该初值。
> 每帧加一，**255 之后回绕到 1**（保留 SN=0 表示复位）。
> 序列号位置**紧接在 MAC CRC 字段之前，属于 MAC 载荷的一部分**。
> 冗余副本应在**最大 0.5 ms** 的时间差内发出。
> 每 VL 可配置是否使用冗余。

规范给的 SN 位宽论证：BAG = 1 ms、SkewMax = 5 ms 的最坏情况下，两帧间最大 SN 偏移远低于 128，回绕安全。

### 2.4 端口语义 §3.3.1.1 — **发现两个潜在缺口**

**采样端口（§3.3.1.1.1.2 In Reception）**：

> The last message stored in a particular sampling port should be able to be read by several partitions.
> **A freshness indication should be associated to each sampling port. This freshness indication should be available to each partition reading the message.**

⚠️ **缺口 1**：规范要求每个采样端口带 **freshness（新鲜度）指示**并对读取方可见。需核对 `rx_port_buf` / `host_if` 是否提供该指示（时间戳或有效期标志）。若没有，这是一条可低成本补齐的合规项。

**队列端口（§3.3.1.1.2）**：

> 队列服务按 **ARINC 653 §2.3.5.6.2** 定义。
> 应能为同一队列端口管理**不同长度**的消息。
> 为保证消息顺序，收发两侧都应按 **FIFO** 纪律管理。
> **每个队列服务实例应能管理最多 8 k octet 的应用数据（因此需要 IP 分片）。**
> 发送方向若缓冲溢出，应向发送分区发出错误指示。

⚠️ **缺口 2**：**8 kB 应用数据 + IP 分片**。本项目当前帧格式是单帧 ≤1518 B、未实现 IP 分片/重组。这是**已知的子集裁剪**，应在设计书 §2.6「子集自界定声明」里显式列为不承诺项（目前未列）。
