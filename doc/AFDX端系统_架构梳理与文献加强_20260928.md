## 1. 系统架构梳理

### 1.1 一句话概括

这个端系统由**两条流水线和一块共享包存储**组成：

- 发送流水把主机消息封装成符合 A664P7 的帧，按 BAG 发出；
- 接收流水把 MAC 字节流送到正确的通信端口，或者丢弃并计数；
- 管理面（SNMP、TFTP/615A、RTC）不单独开网络通道，走 SAP 端口复用同一对流水。

```
             ┌─────────────────────── AFDX_top（单时钟 clk = 125 MHz）───────────────────────┐
 host_bfm ◄──┤ host_if ─► regs / TX·RX VL 配置表 / stats_regs      mgmt: snmp_lite · a615a_tftp · rtc_sync
             │                         ▲ SAP 分流（mgmt_sap_rx）                                 │
             │   tx_port_buf ◄── PMEM 32 KB（32 bit，1W2R，三池 16×2 KB 块）──► rx_port_buf      │
             │        │                                                           ▲              │
             │  TX: tx_vl_scheduler → tx_frame_builder(两遍扫描) → tx_sn_gen → tx_rm → mac_tx_if │
             │  RX: mac_rx_if → rx_vl_lookup(5 拍) → rx_flt → rx_ic → rx_rm → rx_ip_udp_parse   │
             │                → rx_port_buf / rx_block_pool                                       │
             └──────────────────────────────── MAC A / MAC B（GMII 8 bit）───────────────────────┘
```

### 1.2 关键设计决策（节选自设计书 §3.5 和追踪表 §4）

| 决策 | 内容 | 工程要点 |
|---|---|---|
| D1 | 同一套 RTL 支持 `IF_MODE` 0/1 两种接口模式 | 模板端口方向反常，所以用 ready 表示帧包络；另外兼容 GMII 连续字节模式 |
| D2 | 收发共用 32 KB PMEM，用描述符引用 | 帧数据只存一份，RM 等待期间不复制数据 |
| D3 | 单比较器逐项扫描 128 条 VL，按到期年龄最大者优先 | 省面积；最坏扫描时间多 1.024 μs |
| D4 | UDP 校验和两遍扫描，且两遍重叠 | pass1 ≤368 拍，pass2 在偏移 40 才需要校验和，所以不会等 pass1 |
| D7 | RX 用两表 × 2048 桶 × 2 way 哈希，配置期离线选种子 | 支持任意 16 位 VLID，负载 50% |
| D10 | 发送起始错相 | 消除 32 条 VL 同相启动时 801 μs 的排队下界 |
| D12 | IC 之后做 RM，维护 SkewMax 和 seen 状态 | 先到的有效副本优先交付 |
| D13 | PMEM 仲裁：RX 优先，主机延迟 ACK | 保证线速接收时不丢数据 |

### 1.3 当前状态（依据 09-27 续作进度和 09-28 全面核查）

- **功能**：56/56 PASS，lint 通过，T12 故障注入 4/4 检出。
- **时序**：Continue12 post-fit 结果为 **Fmax 99.96 MHz，setup WNS −1.735 ns**，125 MHz 未收敛。最差的 50 条路径全部从 `snmp_lite` 的 `oid_len` 出发，终点是 `vl_stat_mem` 的读地址寄存器。
- **09-28 核查发现的问题**：
  - A01：SNMP 多变量 SET 不是原子的，失败时已有部分写入；
  - A02：SNMP 待决请求会被新请求覆盖；
  - A03：T13 的时延上限只传了参数，没有参与断言；
  - A04：回归判决器存在假绿路径；
  - A05：125 MHz 时序未收敛。
- **覆盖率**：分支加语句合计 67.8%，统计范围含 TB，**没有 covergroup 功能覆盖**。

## 2. 现有文献体系诊断

### 2.1 优点

- 已登记 L001–L095，按 A/B/C/D 分证据等级；
- 建立了 REQ → 决策 → RTL → 测试的追踪链；

这套体系在参赛作品里算很规范的。

### 2.2 主要短板

| # | 短板 | 影响 |
|---|---|---|
| S1 | **正式目录里几乎没有国际同行评审文献**。L001–L095 除了 XAPP1130，基本都是国内学位论文和期刊。英文资料只作为“补充参考”列在目录外，没有稳定 ID | 答辩时，时延上界、RM 算法、哈希查表等核心论断缺少国际一手出处 |

| S3 | **09-24 的《学术文献调研与前沿工程对比》存在引文失真**，详见第 4 节 | 如果答辩时被评委查证，会损害整个文献体系的可信度 |

| S5 | 约 40 条 D 级 CAJ 只登记了题名 | 条目看起来多，实际能支撑结论的有限 |

## 5. 落地建议（按优先级）

1. **先修正第 4 节列出的问题**。成本最低、风险最高，一旦被评委查证会影响整个文献体系的可信度。
2. **下载开放全文并升级证据等级**。优先读这几篇：L105（RM 原始 13 算法）、L107（RM 可靠性）、L101（发送端调度）、L104（VL 设计）、L102。都有 HAL 或作者主页的公开 PDF。读完按页码升到 A 级。
3. **把新文献写进追踪表**：
   - REQ-REL-02 / C-002 → L105、L106、L107，并新增 network babbling / SN 复位丢失测试；
   - REQ-RX-02 / D7 → L109、L110（更正理论出处）、L111（失败回退预案）；
   - REQ-PERF-02 / A03 → L001 中“接收 <150 μs”作为 T13 判据依据，L098 作为 P99 统计依据；
   - REQ-MGMT-02 / A01 → L116（RFC 3416 §4.2.5）；
   - REQ-IMPL-02 / A05 → L115；
   - REQ-QUAL-01 / A03 / A04 → L117、L118。
4. **给目录外的“补充参考”补正式 ID**：UPPAAL-UPenn（很可能就是 L106）、MengLi 学位论文（对应 L107）、Finzi 学位论文（对应 L120）、RFC 系列等，避免“有文件无 ID”。
5. **答辩口径**：国际文献只作为原理、方法和规范依据。性能、正确性、时序三类结论仍回到 56 项回归、post-fit 报告和 STA，与项目现有“文献不是实现证据”的规则保持一致。
