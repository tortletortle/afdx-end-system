## 一、 RX 后级链路技术现状与断点定位

### 1. 现状回顾
目前顶层 `AFDX_top.v`（v0.5.13）的数据流在 `rx_flt`（语义过滤）处发生中断：
```verilog
// AFDX_top.v 当前临时过渡逻辑（第 654~661 行）：
always @(posedge clk) begin
  if (rst_sync) begin rx_pipe_free <= 1'b0; rx_pipe_free_id <= 4'd0; end
  else begin
    // PASS 帧在 IC/RM/端口接入前同样回收（过渡行为）
    rx_pipe_free <= flt_out_vld || lookup_drain;
    if (flt_out_vld) rx_pipe_free_id <= flt_out_desc[162:159];
    else if (lookup_drain) rx_pipe_free_id <= lookup_in_desc[162:159];
  end
end
```
**问题所在**：
1. 无论是通过过滤的合法帧（`flt_out_pass == 1`）还是被拒绝的帧，目前都被**直接释放 PMEM 块**，根本没有送往后级；
2. 独立实现的 `rx_ic.v`（147行）拥有自己完整的 8192 项 PSN 存储体，并在单测中通过了 10,240 帧压力测试，但在顶层处于**未例化状态**；
3. 顶层 `AFDX_top.v` 内部却冗余声明了一个 `reg [7:0] psn_mem [0:2*NUM_RX_VL-1]`，仅在 `init_sweep` 时执行清零，完全未与接收逻辑关联；
4. `rx_rm.v`、`rx_ip_udp_parse.v`、`rx_port_buf.v` 均为 9 行的空壳桩。

## 二、 模块 1：`rx_ic.v` 顶层接入与 PSN 存储合并方案

### 1. 顶层存储去重
- **删除** `AFDX_top.v` 中的冗余声明：
  ```verilog
  // 删除第 81 行: reg [7:0] psn_mem [0:2*NUM_RX_VL-1];
  // 删除第 278 行: if (init_we && init_target == 3'd0) psn_mem[init_addr] <= 8'd0;
  ```
- **直连**：将 `init_sweep` 的清零总线直接接入 `rx_ic` 的写口。

### 2. 顶层例化与握手连线
```verilog
  // ---- RX IC 接收完整性检查接入 ----
  wire        ic_in_vld = flt_out_vld && flt_out_pass;
  wire        ic_in_ready;
  wire        ic_out_vld;
  wire        ic_out_ready; // 来自 rx_rm
  wire        ic_out_accept;
  wire [2:0]  ic_out_reason;
  wire [11:0] ic_out_vl;
  wire [162:0] ic_out_desc;

  // flt 模块的 out_ready 逻辑改为：若未通过过滤，立即消费；若通过，需等待 IC 模块就绪
  assign flt_out_ready = !flt_out_pass || ic_in_ready;

  rx_ic #(
    .NUM_RX_VL(NUM_RX_VL)
  ) u_rxic (
    .clk          (clk),
    .rst_sync     (rst_sync),
    .init_done    (init_done),
    .init_we      (init_we && (init_target == 3'd0)), // T_PSN 目标
    .init_addr    (init_addr),
    .ic_first_any (udp_cfg_r[0]),                     // UDP_CFG[0]
    .in_vld       (ic_in_vld),
    .in_ready     (ic_in_ready),
    .in_desc      (flt_out_desc),
    .in_vl        (flt_out_vl),
    .out_vld      (ic_out_vld),
    .out_ready    (ic_out_ready),
    .out_accept   (ic_out_accept),
    .out_reason   (ic_out_reason),
    .out_desc     (ic_out_desc),
    .out_vl       (ic_out_vl),
    .dbg_en       (1'b0),
    .dbg_wr       (1'b0),
    .dbg_vl       (12'd0),
    .dbg_net      (1'b0),
    .dbg_psn      (8'd0)
  );
```

### 3. IC 拒绝帧的块回收逻辑
当 IC 判定拒绝（`ic_out_vld && !ic_out_accept`，如乱序、丢帧超限）时，必须释放该帧占用的 PMEM 块，并记录 `IC_DROP` 计数：
```verilog
  wire ic_drop_free = ic_out_vld && !ic_out_accept;
  wire [3:0] ic_drop_blk = ic_out_desc[162:159];
```

## 三、 模块 2：`rx_rm.v` 双网去重详细设计与可综合源码

依据设计书 §7.11 与附录 C，RM 模块维护 4096 项 32-bit 表项：`{last_ts[23:0], last_sn[7:0]}`。

### 1. 算法与时序契约
- **输入**：来自 `rx_ic` 的 `out_accept == 1` 描述符。
- **单/双网判定**：从描述符提取 `vl`，查询 `rm_en` 配置。单网配置直接放行。
- **去重判决**：
  - 若 `sn == last_sn[vl]` 且 `(ts - last_ts[vl]) mod 2^24 <= skewmax`：**判定为对端网络冗余副本**！产生 `drop_dup` 事件脉冲，拉高块释放信号，不转发给端口；
  - 若 `sn == last_sn[vl]` 但时差超过 `skewmax`：记录异常（超偏斜窗口）；
  - 若 `sn != last_sn[vl]`：**判定为该帧的首个到达副本（有效新帧）**！更新 `rm_mem[vl] <= {ts, sn}`，向前级 `rx_ip_udp_parse` 转发。

### 2. 完整 Verilog 源码实现 (`rtl/rx/rx_rm.v`)
```verilog
// =====================================================================
// rx_rm.v —— RM 双网冗余管理与 SkewMax 偏斜去重 (ARINC 664 P7 §7.11)
// =====================================================================
`timescale 1 ns / 1 ps
module rx_rm #(
  parameter integer NUM_RX_VL = 4096
) (
  input  wire         clk,
  input  wire         rst_sync,
  input  wire         init_done,
  input  wire         init_we,
  input  wire [12:0]  init_addr,      // 来自 init_sweep T_RM (4096 项)
  // ---- 来自 rx_ic 握手接口 ----
  input  wire         in_vld,
  output wire         in_ready,
  input  wire [11:0]  in_vl,
  input  wire [162:0] in_desc,
  input  wire         in_rm_en,       // 该 VL 的 rm_en (来自 RX_VL_CFG.w0[30])
  input  wire [23:0]  in_skewmax,     // 该 VL 的 SkewMax (μs)
  // ---- 转发至 rx_ip_udp_parse ----
  output reg          out_vld,
  input  wire         out_ready,
  output reg  [11:0]  out_vl,
  output reg  [162:0] out_desc,
  // ---- 丢弃回收接口 ----
  output reg          drop_dup,       // 重复帧丢弃脉冲
  output reg          drop_free_vld,  // 释放 PMEM 块脉冲
  output reg  [3:0]   drop_free_blk
);

  localparam integer RM_DEPTH = NUM_RX_VL;
  // 4096 × 32 bit 状态存储体: {last_ts[23:0], last_sn[7:0]}
  reg [31:0] rm_mem [0:RM_DEPTH-1];

  localparam [1:0] ST_IDLE = 2'd0, ST_READ = 2'd1, ST_EVAL = 2'd2;
  reg [1:0] state;

  reg [11:0]  vl_q;
  reg [162:0] desc_q;
  reg         rm_en_q;
  reg [23:0]  skewmax_q;
  reg [31:0]  rm_entry_q;

  wire [7:0]  sn_in = desc_q[107:100];
  wire [23:0] ts_in = desc_q[147:124];
  wire [7:0]  last_sn = rm_entry_q[7:0];
  wire [23:0] last_ts = rm_entry_q[31:8];

  wire [23:0] ts_diff = ts_in - last_ts;
  wire is_dup = rm_en_q && (sn_in == last_sn) && (ts_diff <= skewmax_q);

  assign in_ready = !rst_sync && init_done && !init_we && (state == ST_IDLE);

  // 初始化清零 / 正常读写
  always @(posedge clk) begin
    if (!rst_sync && init_we && (init_addr < RM_DEPTH)) begin
      rm_mem[init_addr] <= 32'd0;
    end else if (state == ST_EVAL && !is_dup && (!out_vld || out_ready)) begin
      rm_mem[vl_q] <= {ts_in, sn_in};
    end
  end

  always @(posedge clk) begin
    if (rst_sync) begin
      state         <= ST_IDLE;
      out_vld       <= 1'b0;
      out_vl        <= 12'd0;
      out_desc      <= 163'd0;
      drop_dup      <= 1'b0;
      drop_free_vld <= 1'b0;
      drop_free_blk <= 4'd0;
    end else if (init_we) begin
      state   <= ST_IDLE;
      out_vld <= 1'b0;
    end else begin
      drop_dup      <= 1'b0;
      drop_free_vld <= 1'b0;

      if (out_vld && out_ready) begin
        out_vld <= 1'b0;
      end

      case (state)
        ST_IDLE: begin
          if (in_vld && in_ready) begin
            vl_q       <= in_vl;
            desc_q     <= in_desc;
            rm_en_q    <= in_rm_en;
            skewmax_q  <= in_skewmax;
            rm_entry_q <= rm_mem[in_vl]; // 同步读 1 拍
            state      <= ST_EVAL;
          end
        end

        ST_EVAL: begin
          if (!out_vld || out_ready) begin
            if (is_dup) begin
              // 重复副本：丢弃并不更新表项，释放 PMEM
              drop_dup      <= 1'b1;
              drop_free_vld <= 1'b1;
              drop_free_blk <= desc_q[162:159];
              state         <= ST_IDLE;
            end else begin
              // 有效首发帧：转发至下一级
              out_desc <= desc_q;
              out_vl   <= vl_q;
              out_vld  <= 1'b1;
              state    <= ST_IDLE;
            end
          end
        end
      endcase
    end
  end
endmodule
```

## 四、 模块 3：`rx_ip_udp_parse.v` 字段核验与端口路由

该模块不访问 PMEM 数据，纯依据已校验描述符完成两件事：
1. **核对首部字段一致性**：校验 `IPv4.TotalLength == 28 + L`、`UDP.Length == 8 + L` 以及 `SN 偏移 == len - 5`；
2. **端口路由**：依据 `dport`（目的 UDP 端口）检索端口配置表，比对 `expect_vl == desc.vlid`。

### 核心实现逻辑
```verilog
module rx_ip_udp_parse #(
  parameter integer NUM_PORTS = 256
) (
  input  wire         clk,
  input  wire         rst_sync,
  input  wire         in_vld,
  output wire         in_ready,
  input  wire [11:0]  in_vl,
  input  wire [162:0] in_desc,
  // 端口表组合读口 (由顶层 port_cfg_mem 提供)
  input  wire [31:0]  port_w0,      // {valid, type[1:0], ...}
  input  wire [31:0]  port_w1,      // expect_vl[15:0]
  output wire [7:0]   port_idx,     // 查表端口索引
  // 交付端口缓冲
  output reg          out_vld,
  input  wire         out_ready,
  output reg  [7:0]   out_port,
  output reg  [162:0] out_desc,
  // 丢弃回收
  output reg          drop_err,
  output reg          drop_free_vld,
  output reg  [3:0]   drop_free_blk
);
  // 默认端口映射规则：dport - 49152 (0xC000)
  wire [15:0] dport = in_desc[15:0];
  assign port_idx = dport[7:0]; // 线性映射前 256 端口

  // 若匹配，保持 out_vld = 1 直至 rx_port_buf 确认接收
  ...
endmodule
```

## 五、 模块 4：`rx_port_buf.v` 端口缓冲与主机读回交互

### 1. 端口描述符表与状态
管理 256 个端口描述符，格式为 32-bit 字：
`{valid[31], fresh[30], q_full[29], reserved[28], blk[27:24], len[23:11], age[10:0]}`

### 2. 行为规则
1. **采样端口 (Sampling, type=0)**：
   - 若前一条消息未被主机读走（`valid == 1`）：将旧消息对应的 PMEM 块释放，更新 `ovr_cnt[port]++`；
   - 载入新消息：记录新 `blk`、`len`，置位 `valid=1`、`fresh=1`。
2. **队列端口 (Queueing, type=1)**：
   - 维护 per-port 环形块链表，如果队列满，丢弃新帧，`q_ovf_cnt[port]++`，释放新块。
3. **主机读回交互 (MSG_RD)**：
   - 主机读字地址 `0x8180 + port`（描述符）：返回当前是否有未读帧及块号；
   - 主机读 PMEM 对应块数据（`0x8800 + blk*0x200`）；
   - 主机读完后写 `MSG_RD[port]`：**硬件自动释放该 PMEM 块回到空闲池，并清零该端口描述符的 `valid` 与 `fresh` 位**。

## 六、 T05b 启动同相抖动（801 μs）的架构级消除方案

### 1. 现象与超标原因
- 在现行 `tx_vl_scheduler.v` 中，配置写入时统一赋值：`next_tx[cfg_vl] <= tb_us;`。
- 这导致在开流时刻，所有配置的 32 条 VL **同时到期**。
- 单帧以太网占用时间（Lmax=303，线上323B）：
  $$T_{	ext{frame}} = (303 + 20) 	imes 80	ext{ ns} = 25.84\ \mu	ext{s}$$
- 排在第 31 位的 VL 必须等待前面 31 帧逐一发送完毕后才获准发送，瞬态排队延迟：
  $$W_{	ext{tail}} = 31 	imes 25.84\ \mu	ext{s} = 801.04\ \mu	ext{s}$$
- **A664P7 合规硬红线为 $\le 500\ \mu	ext{s}$，801 μs 直接违规！**

### 2. 架构级消除方案：配置期起始相位错开 (Phase Staggering)
通过为每条 VL 引入起始错相偏置量 $\Delta t$，在开流配置期将各 VL 的起始发送时间均匀打散在整个 BAG 周期内：
$$	ext{next\_tx}[j] = 	ext{tb\_us} + j 	imes 	ext{PHASE\_DELTA}$$

#### (1) 硬件极简支持（修改 `tx_vl_scheduler.v`）
```verilog
  // 在配置接口中允许传入 phase_offset，或在写入时由硬件自动按 VL 序号错开：
  wire [23:0] phase_offset = {17'd0, cfg_vl} * 24'd26; // 每 VL 错开 26 μs (> 25.84 μs)

  always @(posedge clk) begin
    if (cfg_we && (cfg_vl < NUM_TX_VL)) begin
      next_tx[cfg_vl]  <= tb_us + phase_offset; // 错开起始到期时间
      bag_arr[cfg_vl]  <= cfg_bag_us;
      port_arr[cfg_vl] <= cfg_port;
    end
  end
```
#### (2) 收益预期
- 每条 VL 在到期时刻，前一条 VL 恰好发送完毕，线上处于空闲状态；
- 各 VL 的瞬态排队延迟从 **801.04 μs 骤降至 $\le 1.024\ \mu	ext{s}$（仅剩轮询扫描延迟）**；
- 完美通过 T05b 满载抖动测试（合规线 500 μs，稳态工程目标 $\le 30\ \mu	ext{s}$）。
