**文档版本**：v1.0.0

**角色定位**：架构设计与审计基准（供编码智能体执行，供审计智能体验收）

## 1. 角色分工与协作界面约定

为了确保项目开发的高质量推进与零回归风险，本项目采用**双智能体分工协作模式**：

1. **编码执行智能体（Coding Agent）**：
   - **职责**：负责按照本文档第 3、4 节给出的精确信号表、逻辑切片与伪代码，在 `rtl/` 及 `sim/` 中落地具体代码修改。
   - **纪律红线**：
     - 严禁擅自修改附录 A/B 已冻结的寄存器映射地址（如 `0x0000~0x8FFF` 空间）；
     - 严禁修改已固化的顶层模块端口名及位宽；
     - 严禁引入任何非单拍互斥的内存操作，避免破坏 BRAM 推断；
     - 每次修改后必须通过 Lint 与现存 26 项测试基线。
2. **架构审计智能体（Architecture & Audit Lead，本角色）**：
   - **职责**：负责架构方案论证、代码审计、数学与时序边界复核、回归门禁核验、文档体系维护。
   - **一票否决权（Veto Criteria）**：
     - 若修改导致现存 26 项测试中任一项失败，直接驳回；
     - 若修改破坏内存守恒（`rx_free_map != 16'hFFC0`），直接驳回；
     - 若引入推断锁存器（inferred latches）或多驱动冲突，直接驳回。

## 2. 架构优化技术审查结论（前序审查摘要）

经过对当前代码库与测试台探针的逐行审计，形成以下指导性结论：

1. **D10 (正交错相 OPS)**：当前 `tx_vl_scheduler.v` 在配置生效时直接 `next_tx <= tb_us`，导致 32 条 VL 同相并发时队尾排队延迟高达 $801.04\ \mu\text{s}$（超标 ARINC 664 P7 的 $500\ \mu\text{s}$ 限制）。采用移位加法器（$26 \times i = 16i + 8i + 2i$）可实现零 DSP 开销的确定性错相。
2. **D11 (级联释放 CPDB)**：`rx_block_pool` 仅有 1 个 `free_pipe` 释放端口。在当前未接入主机 DMA 读出的过渡阶段，测试台（如 T08b、T08d、T12f）严苛依赖好帧与坏帧最终都把块归还到块池（断言 `rx_free_map == 16'hFFC0`）。因此，流水线中的释放信号必须单拍互斥合并，不能截断好帧的回收通道。
3. **D12 (时间戳仲裁 TFA)**：`AFDX_top.v` 原有 Port A 绝对固定优先级仲裁已被数学证明存在**严重缺陷**——若 Net B 帧先到、Net A 帧后到，固定优先级强制先弹出 Net A 帧，导致后级 RM 计算 $\Delta t = t_B - t_A$ 发生 24 位无符号下溢（$\approx 16,777,196 \gg \text{SkewMax}$），致使双网去重失效！必须升级为基于 `rx_desc[147:124]` 物理时间戳的先到先服务（FCFS）仲裁。
4. **D13 (IC 与 RM 职责边界)**：IC 是单网独立完整性校验（Net A 与 Net B 各维护 `psn`），RM 是跨网全局冗余消除（维护全局 `{last_sn, last_ts}`）。两者的存储器语义不同，不可强行合设，但丢弃通道必须统一接入 CPDB。

## 3. 编码智能体执行规范：RTL 修改详细基准

### 3.1 改造项 1：`rtl/tx/tx_vl_scheduler.v` 正交错相机制

> **2026-09-28 核对注（追加，不改原文）**：本改造项**尚未实施，且不建议按原样实施**。当前 `rtl/tx/tx_vl_scheduler.v:131` 仍为 `next_tx[cfg_vl] <= tb_us;`，无 `ENABLE_OPS` 参数；D10 实际由主机错相提交落地（T05b `tb_t05b_jitter.v:162`）。原因：首帧时刻由消息到达决定，`tb_us + 26×vl` 只在开流时消息已就绪才有效，主机稍后提交时各 VL 仍会同时到期。若需硬件保证，应采用按 BAG 相位栅格对齐的 `phase_lock` 方案，见 [第三轮文献补充与设计优化建议](AFDX端系统_第三轮文献补充与设计优化建议_20260928.md) OPT-6 方案 B；实施前须评审，并跑 56 项全量回归＋post-fit STA。


#### 修改目标
消除启动齐步走导致的 801 μs 瞬态排队抖动，使端系统最大发送抖动降至 < 26 μs。

#### 接口要求
在模块参数列表中增加错相使能参数（默认使能，保证 T05b 达标）：
```verilog
module tx_vl_scheduler #(
  parameter integer NUM_TX_VL = 128,
  parameter integer NUM_PORTS = 256,
  parameter integer ENABLE_OPS = 1     // 1: 启用正交错相; 0: 原同相启动
) ( ...
```

#### 逻辑实现要求
在配置写入分支（`cfg_we`）中，替换原有直接赋值：
```verilog
  // ---- 优化前 ----
  // if (cfg_we) begin
  //   next_tx[cfg_vl]  <= tb_us;
  //   bag_arr[cfg_vl]  <= cfg_bag_us;
  //   port_arr[cfg_vl] <= cfg_port;
  // end

  // ---- 优化后 (D10 OPS) ----
  // 错相步长 Δ = 26 μs (基于 Lmax=303B 单帧线上时间 25.84 μs 向上取整)
  // 采用 16 + 8 + 2 无乘法器移位加法
  wire [23:0] ops_offset = ENABLE_OPS ?
      ({13'd0, cfg_vl, 4'b0} + {14'd0, cfg_vl, 3'b0} + {16'd0, cfg_vl, 1'b0}) : 24'd0;

  always @(posedge clk) begin
    if (cfg_we) begin
      next_tx[cfg_vl]  <= tb_us + ops_offset;
      bag_arr[cfg_vl]  <= cfg_bag_us;
      port_arr[cfg_vl] <= cfg_port;
    end else if (pop) begin
      next_tx[pop_vl]  <= tb_us + bag_arr[pop_vl] + 24'd1;
    end
  end
```

#### 注意事项
- VL 0 的 `ops_offset` 计算结果为 0，因此单 VL 测试（T04 Phase 1、T22a）行为与基线绝对一致，零回归风险。

### 3.2 改造项 2：`rtl/top/AFDX_top.v` 双网物理时间戳公平仲裁 (TFA)

#### 修改目标
消除双网入口静态优先级引起的排队时间倒挂，保证 SkewMax 偏斜去重准确性。

#### 修改目标定位
定位 `AFDX_top.v` 约第 638~652 行（双网描述符出队仲裁处）。

#### 逻辑实现要求
```verilog
  // ---- 优化前 ----
  // wire [162:0] lookup_in_desc = rx_desc_valid_a ? rx_desc_a : rx_desc_b;
  // wire lookup_in_vld = rx_stream_en && (rx_desc_valid_a || rx_desc_valid_b);
  // wire lookup_take = lookup_in_vld && lookup_in_ready;
  // assign rx_desc_pop_a = rx_desc_valid_a && (lookup_take || lookup_drain);
  // assign rx_desc_pop_b = !rx_desc_valid_a && rx_desc_valid_b && (lookup_take || lookup_drain);

  // ---- 优化后 (D12 TFA) ----
  // 提取两网物理层首字节时间戳 (位宽 [147:124])
  wire [23:0] ts_a = rx_desc_a[147:124];
  wire [23:0] ts_b = rx_desc_b[147:124];
  wire [23:0] diff_ts = ts_a - ts_b; // 24-bit 模减

  // 判定规则：
  // 1. 若仅 A 有效，选 A；
  // 2. 若仅 B 有效，选 B；
  // 3. 若双网均有效：
  //    - 当 ts_a <= ts_b (即 diff_ts 高位为 0 且 <= 2^23)，选 A；
  //    - 当 ts_a > ts_b (即 diff_ts 跨过半程)，选 B；
  //    - 若时间戳同拍完全相等，网络 A 优先破局。
  wire a_older = rx_desc_valid_a &&
                 (!rx_desc_valid_b || (diff_ts[23] ? 1'b0 : 1'b1));

  wire choose_a = a_older;
  wire [162:0] lookup_in_desc = choose_a ? rx_desc_a : rx_desc_b;
  wire lookup_in_vld = rx_stream_en && (rx_desc_valid_a || rx_desc_valid_b);
  wire lookup_take = lookup_in_vld && lookup_in_ready;

  // 严格保证 pop_a 与 pop_b 互斥，单拍仅弹出一项
  assign rx_desc_pop_a = choose_a && (lookup_take || lookup_drain);
  assign rx_desc_pop_b = !choose_a && rx_desc_valid_b && (lookup_take || lookup_drain);
```

#### 注意事项
- `tb_t12f_top_lookup.v` 包含断言：`if(dut.rx_desc_pop_a && dut.rx_desc_pop_b) bad(...)`。上述逻辑严格保证互斥，完全满足断言。

### 3.3 改造项 3：`rtl/rx/rx_rm.v` 冗余管理去重模块落地

#### 修改目标
从现有 9 行空壳完善为符合 ARINC 664 P7 §7.11 的完整去重模块。

#### 模块接口契约（精确定义）
```verilog
`timescale 1 ns / 1 ps
module rx_rm #(
  parameter integer NUM_RX_VL = 128
) (
  input  wire         clk,
  input  wire         rst_sync,
  input  wire         init_done,
  input  wire         init_we,
  input  wire [6:0]   init_addr,      // 复位表项清零
  
  // 上游输入（来自 rx_ic.v）
  input  wire         in_vld,
  output wire         in_ready,
  input  wire [162:0] in_desc,
  input  wire [6:0]   in_vl,
  input  wire         in_accept,      // 来自 IC 的判定结果
  input  wire [2:0]   in_reason,

  // 下游输出（转发至 rx_port_buf / 测试过渡回收）
  output reg          out_vld,
  input  wire         out_ready,
  output reg  [162:0] out_desc,
  output reg  [6:0]   out_vl,
  output reg          out_forward,    // 1: 转发有效帧; 0: 冗余剔除/丢弃
  output reg          drop_dup,       // 重复帧事件脉冲 (1 拍)
  output reg          drop_skew,      // 超 SkewMax 异常脉冲 (1 拍)

  // 内存释放通道（级联输出给 block_pool）
  output reg          free_req,
  output reg  [3:0]   free_id
);
```

#### 核心状态与算法
1. 存储器：`reg [31:0] rm_table [0:NUM_RX_VL-1];`，格式 `{valid, 7'd0, last_sn[7:0], last_ts[15:0]}` 或完整 24 位时间戳；
2. 判决式：
   - 若 `!in_accept`（IC 已拒绝），直接 `out_forward = 0`，并触发 `free_req`；
   - 若 `in_accept`：
     - 若该 VL 首次接收（`!valid`），则 `valid <= 1`，更新 `last_sn/last_ts`，`out_forward = 1`；
     - 若 `sn == last_sn` 且 `(ts - last_ts) <= skewmax`，判定为冗余副本，`drop_dup <= 1`，`out_forward = 0`，触发 `free_req`；
     - 若 `sn != last_sn` 或超时，更新表项并 `out_forward = 1`。

### 3.4 改造项 4：`rtl/top/AFDX_top.v` 级联释放通道 (CPDB) 整合

#### 修改目标
确保 FLT 拒绝帧、IC 拒绝帧、RM 去重丢弃帧、Lookup 冲刷帧以及过渡期好帧全部单拍可靠回收，杜绝 Block Pool 泄漏死锁。

#### 逻辑整合规范
```verilog
  // 级联释放信号收集
  wire flt_drop_req  = flt_out_vld && !flt_out_pass;
  wire [3:0] flt_drop_id = flt_out_desc[162:159];

  wire ic_drop_req   = ic_out_vld && !ic_out_accept;
  wire [3:0] ic_drop_id  = ic_out_desc[162:159];

  wire rm_drop_req   = rm_out_vld && !rm_out_forward;
  wire [3:0] rm_drop_id  = rm_out_desc[162:159];

  // 过渡期：最终接收的有效帧在端口未接通前同样回收
  wire pass_ret_req  = rm_out_vld && rm_out_forward;
  wire [3:0] pass_ret_id = rm_out_desc[162:159];

  // 统一级联互斥释放驱动
  always @(posedge clk) begin
    if (rst_sync) begin
      rx_pipe_free    <= 1'b0;
      rx_pipe_free_id <= 4'd0;
    end else begin
      rx_pipe_free <= flt_drop_req || ic_drop_req || rm_drop_req ||
                      pass_ret_req || lookup_drain;
      if (flt_drop_req)        rx_pipe_free_id <= flt_drop_id;
      else if (ic_drop_req)   rx_pipe_free_id <= ic_drop_id;
      else if (rm_drop_req)   rx_pipe_free_id <= rm_drop_id;
      else if (pass_ret_req)  rx_pipe_free_id <= pass_ret_id;
      else if (lookup_drain)  rx_pipe_free_id <= lookup_in_desc[162:159];
      else                    rx_pipe_free_id <= 4'd0;
    end
  end
```

## 4. 编码执行后的自查清单（Audit Gate Checklist）

编码智能体完成代码修改后，必须逐项对照下表执行自查，并将自查日志交由审计智能体复核：

| 检查项编号 | 门禁名称 | 验收标准 / 命令 | 责任与判定 |
|---|---|---|---|
| **GATE-01** | **语法与静态分析** | 执行 Verilator / eLinx Lint，**0 `%Error`**，无未闭合时序或隐式锁存器 | 编码者必须自检通过 |
| **GATE-02** | **26 项全量回归基线** | 运行现存 `sim/tests.manifest` 26 项用例，**26/26 必须全部 PASS** | 核心防倒退红线 |
| **GATE-03** | **内存守恒核查** | 在 T08b、T08d、T12f 测试结束点，断言 `rx_free_map == 16'hFFC0` 恒成立 | 杜绝 PMEM 块池泄漏 |
| **GATE-04** | **双网互斥出队核查** | `tb_t12f` 中 `pops` 计数与输入帧数 1:1 匹配，无同拍双弹 | 保证 TFA 仲裁正确性 |
| **GATE-05** | **T05b 启动抖动合规** | 32 条 VL 满载并发启动时，最大等待抖动 **$\le 500\ \mu\text{s}$**（目标 $< 26\ \mu\text{s}$） | A664P7 强制达标项 |

## 5. 审计负责人后续响应
