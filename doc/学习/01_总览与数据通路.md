## 1. 一句话定位

**解决什么问题：** 机载应用需要确定性航空以太网端点——本作品实现 **AFDX 端系统（ES，End System）全硬件**，不靠片上软核跑协议栈。

**怎么做：** 网络侧 **GMII A/B 双网**；主机经扩展 `host_*` 读写；功能与指标由**本仓自建 TB**验收（评委也用自建 TB，不是官方 A664 套件）。

**代码在哪：** `rtl/top/AFDX_top.v` L13 `module AFDX_top`；数据面 `rtl/tx/*`、`rtl/rx/*`；管理面 `rtl/mgmt/*`。

## 4. AFDX 入门（白话 + 本设计模块）

### VL（Virtual Link，虚拟链路）

VL 是一条**有编号的逻辑管道**：像「合同规定的专用车道」，帧按 VLID 走，带宽按配置预算，不是随意抢带宽。发送侧按 VL 调度；接收侧先查表认 VL。本设计：TX `tx_vl_scheduler`（`rtl/tx/tx_vl_scheduler.v`）；RX `rx_vl_lookup`（`rtl/rx/rx_vl_lookup.v`）。

### BAG（Bandwidth Allocation Gap，带宽分配间隔）

BAG 是同一 VL **两次发送起点之间的最小间隔**：像「同一车道至少隔多久才能再发一车」。调度器到期才允许该 VL 再发。数字例：BAG=**1 ms**，参数 `CLK_FREQ_HZ`=**125e6**（`AFDX_top.v` L20）→ \(1\times10^{-3}\times125\times10^{6}\)=**125000 拍**（`tx_vl_scheduler` 内 `CYCLES_PER_US=125`，BAG_us×125）。注意：125 MHz 是**仿真拍/GMII 字节拍参数**；`fmax_mhz`=41.66 标 **I**，勿说板级时序已按 125 签核。本设计：`tx_vl_scheduler`。

### SN（Sequence Number，序号）

每 VL 发一帧，SN **递增**，接收端用它判断丢帧/乱序。像「快递流水号」。本设计：发 `tx_sn_gen`（`rtl/tx/tx_sn_gen.v`）；收完整性 `rx_ic`（`rtl/rx/rx_ic.v`）。

### A/B 双网

同一帧可在 **A、B 两套物理网**各发一份，抗单点链路故障。发送侧复制；接收侧去重，主机只见一次。本设计：TX `tx_rm`（`rtl/tx/tx_rm.v`）；RX `rx_rm`（`rtl/rx/rx_rm.v`）。端口见 §6。

### IC（Integrity Checking，完整性检查）

按 SN 规则检查缺号、非法跳变等。像「核对流水号是否连续合理」。本设计：`rx_ic`（`rtl/rx/rx_ic.v`），参数 `IC_EN`。

### RM（Redundancy Management，冗余管理）

在 SkewMax 时间窗内，对 A/B 副本 **只保留一份**交给上层。像「两路快递先到的收，后到同号丢」。旁证：T10 `t10_fwd/dup/skew`=56/46/3。本设计：`rx_rm`；发送侧双网复制是 `tx_rm`（同名不同侧）。**顺序：先 IC，再 RM。**

## 5. 数据通路（ASCII）

### TX（主机 → 网络）

```
host
  → tx_port_buf          # 端口队列 / 待发消息缓存
  → tx_vl_scheduler      # 按 BAG 选可发 VL（最早到期优先）
  → tx_frame_builder     # 组 Eth/IP/UDP/SN 帧
     + tx_sn_gen         # 该 VL 序号
  → tx_rm                # A/B 字节级复制
  → mac_tx_if            # 前导/SFD/FCS/IFG，出 GMII
  → GMII A/B
```

路径：`rtl/tx/tx_port_buf.v` … `rtl/tx/mac_tx_if.v`（职责见设计文档 §2.1）。

### RX（网络 → 主机）

```
GMII A/B
  → gmii_rx_strip        # 剥前导/SFD
  → mac_rx_if            # MAC 校验、写 PMEM、出描述符
  → rx_vl_lookup         # 哈希查 VL 索引
  → rx_flt               # valid / VLID / 网 / Lmax 过滤
  → rx_ic                # SN 完整性
  → rx_rm                # SkewMax 去重
  → rx_ip_udp_parse      # IP/UDP 解析、交付类型
  → rx_port_buf          # RX 端口消息队列
  → host
```

路径：`rtl/rx/gmii_rx_strip.v` … `rtl/rx/rx_port_buf.v`。

### 手绘步骤（答辩白板）

1. 左画「host」，右画「GMII A/B」。
2. 上半 TX：6 格，`tx_sn_gen` 并在 `tx_frame_builder` 旁。
3. 下半 RX：9 格；在 `rx_ic`/`rx_rm` 旁写「先完整性，再去重」。
4. 圈 `tx_vl_scheduler`：「BAG=1ms → 125000 拍（仿真）」；圈 `tx_rm`/`rx_rm`：「复制 / 去重」。

## 7. 当日自检（5 题）

1. 一句话：本作品解决什么问题？网络口与主机口各叫什么？
2. BAG=1 ms、仿真 `CLK_FREQ_HZ=125e6` 时，调度间隔是多少拍？能否据此说「板级已按 125 MHz 签核」？
3. TX 链上谁管 BAG？谁复制 A/B？RX 链上谁做 IC、谁做 RM？顺序是什么？
4. 吞吐与抖动各举一个 metrics key 及数值；官方 SFD→SFD 时延应标 P / I / F 哪一等？
5. 指出 `AFDX_top.v` 中 GMII B、host、pps/rtc 大概行号与各 1～2 个端口名。

<details>
<summary>答案</summary>

1. AFDX ES 全硬件端系统；网络 GMII A/B，主机 `host_*`；自建 TB 验收（§1 + §6）。
2. 125000 拍；**不能**——125e6 是仿真拍参数；`fmax_mhz`=41.66 仅 I、未闭合（§4 BAG）。
3. BAG→`tx_vl_scheduler`；复制→`tx_rm`；IC→`rx_ic`，RM→`rx_rm`；顺序 **IC 在 RM 前**（§5 RX）。
4. 例：`t42_tx_a_mbps`=131.072；`t42_jitter_max_us`=5.016（或 `t89_max_jit_ns`=72）。官方 SFD→SFD 标 **I**，勿称已测（§3）。
5. GMII B ≈ L65–70（如 `tx_data_b`/`rx_data_b`）；host ≈ L72–78（如 `host_cs`/`host_addr`）；pps/rtc ≈ L80–82（`pps_in`/`pps_out`/`rtc_time_us`）。
