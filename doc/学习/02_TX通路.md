# 02 TX 通路

> 队员答辩学习。顺序：**问题 → 原理 → 代码**。  
> 链：`tx_port_buf` →（可选 `tx_message_store`）→ `tx_vl_scheduler` → `tx_frame_builder`+`tx_sn_gen` → `tx_rm` → `mac_tx_if` → GMII A/B。  
> 数字仅用下列 T/metrics；**P** 只覆盖对应 TB。口径：勿用第1节禁用宣称词；详见 `07_答辩问答与口径.md` §D。

---

## 先背两句

1. **BAG 到期才发**：同 VL 两次起点至少隔一个 BAG；例 BAG=1 ms、`CYCLES_PER_US=125` → **125000 拍**。证据 T05b `startup_jitter=2us`、`steady=0`（`t05b_*`）；T05c 预算拒载。  
2. **A/B 可各发一份**：`tx_rm` 按 `en_a`/`en_b` 复制。吞吐：T42 `t42_tx_a_mbps`=**131.072**；T90 `t90_tx_a/b_mbps`=**679.188**（128 VL）。

## 1. `tx_port_buf`

**1. 解决什么问题**  
主机 commit 后，消息如何占块、排队，并告诉调度器「某端口有货」？

**2. 原理**  
描述符 + TX 块池：`free_map` 标空闲，`lowest_one` 分配；采样可覆盖，队列按 depth；`sch_req`=`valid_map`。  
例：无空闲块 → `commit_rej`，`pmem_exhaust_cnt++`，不把坏描述符交给调度。

**3. 代码位置**  
`rtl/tx/tx_port_buf.v`：`module tx_port_buf` **L388**；位图/`valid_map`/`sch_req` **L442+**；W 级 `always` **L684+**（写意图；后续 always 落 `free_map`/`valid_map`）。

**4. 对应测试**  
T04/T04g 组帧链；T27 pass；T34p pass。等级 **P**（该 TB）。

**5. 评委追问**  
- `sch_req`？`valid_map`，有待发消息的端口为 1。证据：L442+。  
- 块何时还？builder `blk_free` → 本模块回池。证据：同文件 free 路径。  
- 测了啥？T04/T04g 入队→出线；吞吐旁证 `t42_tx_a_mbps`。

---

## 2. `tx_message_store`

**1. 解决什么问题**  
超长消息分片时，谁管整消息所有权与按片 take？

**2. 原理**  
默认**不用**；仅顶层 `TX_MESSAGE_CHAIN`（如 `TX_MESSAGE_CHAIN_BLOCKS=4`）开启。一次 commit 管多块，take 按片授予。  
例：8192 B、2 KiB×4 块。专用预言机薄 → 多标 **I**。

**3. 代码位置**  
`rtl/tx/tx_message_store.v` **L7** `module tx_message_store`；开关在 `AFDX_top` 参数。

**4. 对应测试**  
无专用独立 T → **I**；全量旁证可提 T27/T34p pass，勿外推「任意分片已全测」。

**5. 评委追问**  
- 默认开吗？不开，要开链参数。证据：顶层参数。  
- 与 `tx_port_buf`？链式替换/并联所有权，小帧非必经。  
- 能说分片认证吗？不能；**I**。

## 3. `tx_vl_scheduler`

**1. 解决什么问题**  
多 VL 有货时，谁保证 BAG 并选出下一发？

**2. 原理**  
FSM：`ST_SCAN`→`ST_TAKE`→`ST_HOLD`→`ST_GO`。SCAN：**8 路/拍、16 拍扫 128 VL**，选 age 最大且 ready；GO 发 `start_vld`。  
**BAG 锚定（禁止写成 `next_tx += bag`）：** `pop` 时 `next_tx ← cycle_count + bag_arr`（`tx_vl_scheduler.v` **L207**）——以**实际上线时刻**为锚再加一整 BAG；延迟后同 VL 间隔仍 ≥ BAG，不会追赶。长阻塞恢复专用场景：**未单独测**（旁证 T05b/T05c/T27）。  
例：BAG=1 ms → **125000 拍**。`PREPARE_CYCLES` 可提前准备。

**3. 代码位置**  
`rtl/tx/tx_vl_scheduler.v` **L32**；FSM **L107–111**；`bag_arr`/`next_tx` **L81**，写口 **L201–208**；`PREPARE_CYCLES` L39。

**4. 对应测试**  
T05b：`startup_jitter=2us`、`steady=0`（`t05b_*`）；T05c 预算拒载；T27 pass。旁证 T13 `t13_worst_total_ns`=**243416**。

**5. 评委追问**  
- 为何 16 拍扫完？128/8=16。证据：L107。  
- BAG 用 μs 还是拍？内部整拍：`cfg_bag_us×CYCLES_PER_US`。证据：L201–208。  
- 抖动？T05b 稳态 0（该压力档，勿外推全 BAG 档）。

## 4. `tx_frame_builder`

**1. 解决什么问题**  
调度只给 VL/块/长度，谁拼 Eth/IP/UDP/SN 字节流？

**2. 原理**  
FSM：`ST_IDLE`→`ST_SETUP`（锁存首部、折校验和）→`ST_EMIT`（按 `out_rdy` 吐字节）。L≈1…1471；HDR 42 B。  
例：L=64 → IP total=28+64、UDP len=8+64；末字节收完 `done` 并 `blk_free`。

**3. 代码位置**  
`rtl/tx/tx_frame_builder.v` **L34**；FSM IDLE/SETUP/EMIT **L98–101**。

**4. 对应测试**  
T04/T04g 组帧链；console **TX_pipe CASE3=448 ns**；T89 `t89_tx_commit2sfd_max_ns`=**3384**（与 T13 分列，见文末）。

**5. 评委追问**  
- SN 从哪来？`snap_req`→`tx_sn_gen`，SETUP 锁入。  
- A/B 字节差？SMAC 第 6 字节（`out_byte_a`/`out_byte_b`）。  
- 长度错？`len_err`，调度弹在途项。证据：同模块。

---

## 5. `tx_sn_gen`

**1. 解决什么问题**  
每 VL 序号谁发、谁在真正上线后才递进？

**2. 原理**  
`sn_cur[vl]`：snap 取当前（0→首次发 **1**）；`commit`（经 `tx_rm.frame_done`）后递进；**255→1，不用 0**（`SN_MAX`/`SN_FIRST`）。  
例：同拍 commit+snap 用旁路拿新值。

**3. 代码位置**  
`rtl/tx/tx_sn_gen.v` **L25**；`sn_cur` always **L74–81**；`SN_MAX`/`SN_FIRST` L50–51。

**4. 对应测试**  
随 T04/T04g、T27；无单独 SN-only key → 场景内 **P**，勿称全错误笛卡尔积已测。

**5. 评委追问**  
- 为何不在 snap 递进？失败可 `cancel`，避免空耗号。  
- 255 之后？回 1。证据：L50–51。  
- 证据链？builder `snap_*` + rm `frame_done`→`commit`。

---

## 6. `tx_rm`

**1. 解决什么问题**  
同一逻辑帧如何按配置只发 A、只发 B、或 A/B 都发？

**2. 原理**  
`sof` 锁存 `net_mode`→`en_a`/`en_b`；两使能路都 `rdy` 才前进；`frame_done` 等使能路 MAC done 对齐后再给 SN commit。  
例：`net_mode=2'b11` → A/B 各一份；`2'b01` 仅 A。

**3. 代码位置**  
`rtl/tx/tx_rm.v` **L13**；`en_a`/`en_b` 与复制 **L48–71**。

**4. 对应测试**  
T42 `t42_tx_a_mbps`=**131.072**；T90 `t90_tx_a/b_mbps`=**679.188**；T89 `t89_pass`。

**5. 评委追问**  
- 与 RX `rx_rm`？发送复制、接收去重，别混。  
- 为何合成 `frame_done`？FIFO 延迟，done 时可能已进下一帧。证据：同文件注释+实现。  
- 双网吞吐？T90 128 VL 上列 key。

## 7. `mac_tx_if`

**1. 解决什么问题**  
谁把字节流变成线上帧（前导/数据/FCS/间隙）？

**2. 原理**  
FSM：`ST_PRE`→`ST_DATA`→`ST_FCS`→`ST_IFG`（另有 IDLE/POST）。`IF_MODE`：0 偏包络；1 偏逐字节 DV+FIFO。  
例：IFG=12 字节槽；FCS 4 字节。

**3. 代码位置**  
`rtl/tx/mac_tx_if.v` **L22**；FSM PRE/DATA/FCS/IFG **L95–101**。

**4. 对应测试**  
T04/T04g；T42 `t42_tx_commit_to_eof_max_us`=**16.08**；T89 `t89_tx_commit2sfd_max_ns`=**3384**、`t89_max_tx_ns`=**15536**、`t89_pass`。

**5. 评委追问**  
- IF_MODE 为何重要？包络与逐字节时延口径不同，数字勿混。  
- `frame_start` 给谁？调度器 BAG 计时（线上起始）。  
- 吞吐？T42/T90 上列 mbps。

## 一帧从主机提交到线上发出（时间线）

逻辑级：`msg_commit` → `tx_port_buf` 占块/`sch_req` → `tx_vl_scheduler` SCAN/TAKE/HOLD/GO → `tx_frame_builder` SETUP/EMIT + `tx_sn_gen` snap → `tx_rm` 复制 → `mac_tx_if` PRE/DATA/FCS → GMII/SFD 侧可见。

**分列（IF_MODE/剧本不同，勿加总、勿混称）：**

| 口径 | 场景 | 数 | key/出处 |
|---|---|---|---|
| 管道内部 CASE3 | T13 | **448 ns** | console `TX_pipe` CASE3 |
| ES 最差单帧 Total | T13 | **243416 ns** | `t13_worst_total_ns` |
| commit→SFD | T89 | **3384 ns** | `t89_tx_commit2sfd_max_ns` |
| TX 侧相关上限 | T89 | **15536 ns** | `t89_max_tx_ns`；`t89_pass` |

拍数直觉（仿真拍参数，**不是**器件已跑满该频）：1 拍=8 ns → 448 ns≈56 拍；3384 ns≈423 拍。BAG 1 ms=125000 拍，与管道时延不同量级。
