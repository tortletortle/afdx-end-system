## 4. 测出过的真 bug（五则故事）

出处：测试报告 §8。

### D1 · chipsim 漏接 `rx_error`

- **现象：** 缩配顶层 `rx_error*` 悬空 → GMII RX 遇 X 进 DROP，回环 `MSG_CNT=0`。
- **根因：** `AFDX_top_chipsim.v` 未引出/接到 `u_es` 的 `rx_error` / `rx_error_b`。
- **修法：** 补端口并接 0（或驱动）；新增 `tb_chipsim_smoke.v`。
- **回归：** **T88a**（修前 FAIL / 修后 PASS）。

### D5 · T89 PSN 污染

- **现象：** 多阶段指标场后接官方 e2e，IC **PSN 被前段污染** / 共享 VL_RX 串扰。
- **根因：** 连续激励未 hard re-init；配置曾共享 RX 索引。
- **修法：** TB 独立 VL_RX；jit32 后 `wait_init` 再跑 e2e。
- **回归：** **T89**（checks + Python 复算）。

### D6 · SAP ready 门控

- **现象：** SAP 忙时仍对同一描述符重复接收。
- **根因：** 入站 valid 未与 `sap_engine_ready` 联合门控。
- **修法：** `AFDX_top`：`prs_to_sap && sap_engine_ready`。
- **回归：** **T15 / T15g**（并入现行全量）。

### D7 · TFTP 主机地址位宽

- **现象：** 地址映射 warning / 宽度不一致风险。
- **根因：** 16 位基址减法后未显式取窗内 13 位。
- **修法：** `host_addr - 16'hCC20` 再取 `[12:0]`；穷举有效窗。
- **回归：** 地址穷举脚本 + 相关全量项。

### D8 · 管理面上线缺陷（写 T24 时暴露）

- **现象：** 管理面能写 PMEM，调度却拿到 `blk=0` / `len=X` 坏描述符 → builder 卡死；响应 FSM 曾抢走观测窗字节致 T15/T16 FAIL。
- **根因：** 误用主机 `MSG_WR` 的 `port_type`/`port_depth`；响应上线未加开关。
- **修法：** 管理面固定 type=2、深度取真实 SAP；响应经 PMEM→`msg_commit`，**CTL[9]** 开关。
- **回归：** 当时定向 **T15/T16**；现行 SNMP/管理相关 T 计入 145。
