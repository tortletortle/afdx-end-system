## 3. 哪份资料负责什么

| 信息 | 维护位置 |
|---|---|
| 需求与赛方约束 | 总体设计书 + 赛方答复原文；我方假设显式标注 |
| 协议和模块接口 | 总体设计书现行章节；实现偏差登记后闭环，不能静默改规格 |
| 寄存器 | `doc/regs.yaml`，`tools/gen_regs.py` 核对附录 A 与生成头 |
| 地址布局 | `tools/fix_addr.py` 的 LAYOUT；`tools/check_addr.py` 复核 |
| BAG/Q20 算术 | `tools/bag_model.py`，正文数字由校验器对账 |
| 实际行为 | 当前 RTL/TB + 相应运行证据；不以历史 PASS 推断新改动正确 |
| 当前完成/未完成与下一步 | `当前进度_20260923.md` / `后续计划.md`（`项目现状.md` 只作历史快照） |

资料冲突时记录“哪一项、两边说法、证据、待决策人/条件”，不要通过改校验器放宽判据取得假通过。

## 4. 维护规则

- **不重复维护完整规格**：概览只摘要并链接到设计书，避免复制地址表和位域表。
- **区分四类陈述**：设计目标、已有实现、限定范围的验证结论、历史记录。
- **更新状态必须附证据**：日期、源码版本或工作树标识、命令、模式、测试集合、退出码、日志路径；性能还要有时钟与量测边界。
- **全量必须可核对**：CSV ID/配置与当次 manifest 完全一致且全为 PASS。子集结果不能与历史结果相加冒充一次全量。
- **变更后检查**：文档执行严格门及链接检查；RTL/脚本执行相关 lint/仿真。生成器默认检查与写入开关分开使用。
- **历史不篡改**：工作记录追加后续结论，不把当时的失败改成成功；过期展示应加醒目标记。三份 HTML 已于 09-24 加顶部历史横幅，正文保持原样。
- **后续若迁移目录**：先清点脚本固定文件名、Markdown/HTML 链接、设计书引用，再统一迁移并验证；本轮不做物理迁移。
