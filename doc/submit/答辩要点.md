## 1. 为什么 Fmax 是 41.66 MHz，与 125 MHz GMII 什么关系？（全队同一版）

- **125 MHz**：仿真与 TB 的 GMII 字节节拍（功能验证时钟），不是「芯片已在板上跑到 125」。
- **41.66 MHz**：满配代理器件（EP4SGX530 类）post-fit 实测 Fmax，Setup −16.005 ns；目录 `out/baseline_full140_fit_sta_20261018_223600/`；宣称等级 **I（未闭合）**。
- 赛方未把「Fmax≥线速」写成硬门槛原句；我们如实标 I，不装签核。
- **禁止**：说「Fmax≥125 已签」；用历史 128.44（旧源码）冒充现行。

## 2. 为什么自研 MAC，没用 eLinx IP？

- 赛题交付是 **ES 协议行为 + 自建 TB**，接口按组委会确认的 **GMII A/B 双网字节口**。
- 自研 `mac_tx_if` / `mac_rx_if`（及 strip）便于把前导/FCS/IFG、IF_MODE、与上层 BAG/IC/RM 同一套仿真闭环。
- eLinx 用作 **综合与工程入口**（指南「eLinx 软件编译及仿真」），不是必须绑定其以太网 IP 才能得分。

## 3. 128 TX / 4096 RX 怎么验证？口径是什么？

- **表容量 / 查找**：T08f、T12* 等写读与查找次数（见测试报告 §3），不是「4096 路同时收」。
- **调度压力**：T05b 等为指定 BAG/VL 场景；**不能推出**合法 BAG 全档或 128 VL 满载吞吐（未测则标 F）。
- 满配参数可综合（eLinx cells/altsyncram），≠ 满配吞吐已测。

## 4. 「2 ms」的起止点？

- 若汇报涉及加卸载/大消息时延：必须说明 **从哪一拍/哪一寄存器到哪一拍**（以对应 TB 为准），不得口头改成「整网 2 ms」。
- 现行公开口径：完整 8 kB 消息「2 ms 达标」等 **未作为已签 P**；见先读「不能宣称」与测试报告边界。
- 被问到：指到具体 T 与 console 行；没有就说 **未测 / 不宣称**。

## 5. 为什么在 1G GMII 上跑 100 Mbps AFDX？

- 物理/仿真接口采用 **1G GMII 字节节拍**（125 MHz×8 bit），便于与常见 MAC/FPGA 模型对齐。
- AFDX 侧用 **BAG + 份额** 把各 VL 聚合带宽约束在配置预算内（规范带宽 Σ 场景见 T05c 等）。
- 「口是 1G、业务按 AFDX 整形到百兆量级配置」——接口速率 ≠ 已声明的 VL 预算。

## 6. 预言机和 RTL 同一批人写，怎么保证可信？

三点并列说，不夸大：

1. **外置黄金 / Python**（`sw/golden/` 等）与部分 TB 双轨（测试报告 §1.2）。
2. **负控变异**：故意改坏期望 FAIL（mutants 表）。
3. **双仿真器**：Questa 功能全量；ModelSim SE 门级 T88b；eLinx GUI 行为仿真人工截图。

仍要承认：不是独立认证实验室；PASS 只覆盖该 TB 标题范围。

## 7. 615A、SNMP 的范围和依据？

- **子集实现**：SNMP lite、TFTP/615A 加卸载相关模块在管理面；以赛题与答疑 + 已跑 T15/T24/T25 等为界。
