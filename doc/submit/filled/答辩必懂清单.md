## 1. BAG 调度（`tx_vl_scheduler`）

1. **一句话**：按每 VL 的 BAG 到期时刻选谁发，保证同 VL 帧间隔 ≥ BAG，超额则记违例。
2. **原理**：`CYCLES_PER_US=125`（125 MHz 拍）；`cfg_bag_cycles = bag_us × 125`。8 路并行扫 128 VL（一轮 16 拍）。选中后 `sch_take`→`start_vld`；`pop` 时 `next_tx[vl] ← cycle_count + bag_arr[vl]`（L207，以实际上线时刻为锚，非 `+=`）。例：BAG=1000 μs → 125000 拍；若入选时 `age ≥ bag_cycles` 则 `bag_viol` 脉冲。长阻塞恢复专用场景未单独测。
3. **代码位置**：`rtl/tx/tx_vl_scheduler.v`  
   - 参数 `CYCLES_PER_US` **L35**；状态 `ST_SCAN/TAKE/HOLD/GO` **L107–110**  
   - 主 FSM `always @(posedge clk)` **L221**；`case (st)` **L233**；`start_vld`/`bag_viol` **L226–232**  
   - 关键信号：`start_vld`、`sch_take`、`bag_viol`、`bag_ovf_cnt`、`next_tx`/`bag_arr`
4. **对应测试**：T05b（压力抖动）/ T05c（超载 CFG_ERR）/ T27（合法 BAG 1…128 ms 扫档）/ T90（128 TX 同时活动）。结果：全量计入 `full_pass`/`full_n`=145；T05b 稳态抖动见 `0`；T90 `t90_pass` **P**。等级：**P**（各 TB 标题范围）；任意 BAG×Lmax 笛卡尔积 **F**。
5. **追问**  
   - BAG 锚点在哪？→ 线上 MAC `frame_start` 周期，见模块头注释与 `frame_permit`。  
   - 为什么仿真用 125 MHz？→ 与 GMII 字节节拍对齐；**不是**「Fmax 已签」。  
   - 超额怎么表现？→ T05c 应拒；本模块 `bag_viol`/`bag_ovf_cnt`；BAG BMC 仍 **F**（`bmc_bag_grade`）。

## 2. 帧构建与 SN（`tx_frame_builder` / `tx_sn_gen`）

1. **一句话**：把端口消息打成 AFDX 帧（ETH/IP/UDP + 载荷 + pad + SN）；每 VL 的 8 bit SN 按协议回绕。
2. **原理**：布局 `DMAC6 SMAC6 ET2 IP20 UDP8 | payload | pad | SN1`，FCS 由 MAC 附加。`SN`：复位后首帧发 1，永不发 0；255→1。例：`L=17` 字节载荷 → 帧长(不含 FCS)=`max(60,43+L)=60`；`snap_req` 取 SN 后 `ST_EMIT` 吐字节。
3. **代码位置**  
   - `rtl/tx/tx_frame_builder.v`：布局注释 **L18–20**；次态 `ST_IDLE/SETUP/EMIT` **L245–252**；时序 `always` **L255**；`case (st)` **L278**；`snap_req`/`sn` **L62–64, L291**  
   - `rtl/tx/tx_sn_gen.v`：`SN_MAX/FIRST` **L50–51**；`sn_tx` **L66**；阵列写 **L74–80**；申请 `always` **L86–118**（`snap`/`snap_ack`/`commit`）
4. **对应测试**：T04/T22 回环组帧；T89/T90 吞吐与 SN 路径；T08e/T09 族对端 IC 用同一 SN 语义。结果：T89 ES 总占用 **5976 ns**（`p_c0_t89` L33）**P**；T90 TX A/B **679.188 Mbps** **P**。等级：**P**；「SN 全错误笛卡尔」**F**。
5. **追问**  
   - SN=0 发不发？→ 不发；`sn_tx` 在 `SN_RST` 时强制 1（L66）。  
   - pad/SN 进不进 UDP 校验和？→ 不进（O-02，builder 头注释 L178）。  
   - FCS 谁算？→ `mac_tx_if` 附加 CRC32，builder 不含 FCS。

## 3. MAC 收发（`mac_tx_if` / `gmii_rx_strip` / `mac_rx_if`）

1. **一句话**：TX 按 GMII 节拍吐前导码/数据/FCS；RX 剥前导码并流式校 FCS/IP/UDP，坏帧不放行。
2. **原理**：TX：`ST_PRE` 七个 `0x55` + SFD `0xD5`，再数据，再 4 B FCS（低字节先）。RX strip：数满 7×`55` 后见 `D5` 进 BODY。例：最小帧体 60 B + FCS 4 → `mac_rx_if` `FRAME_MIN=64`（FCS_MODE≥1）。
3. **代码位置**  
   - `rtl/tx/mac_tx_if.v`：CRC 例化 **L91–92**；FSM `ST_FCS` **L98**；主 `always`/`case (st)` **L142–154**；`tx_valid` mux **L135–137**  
   - `rtl/rx/gmii_rx_strip.v`：状态 `PRE/BODY/DROP` **L18**；`always` **L21**；SFD 判定 **L35–36**（`0xD5`→`BODY`）  
   - `rtl/rx/mac_rx_if.v`：`CRC_RESIDUE` **L63**；`desc_vld` **L36**；主 `always` **L170**；`fcs_bad`/`crc_err` **L150, L210**
4. **对应测试**：T08* 入站；T22/T22g 真回环；T88b 公开端口门级 S1–S3；T42/T89/T90 IF_MODE=2。结果：门级 `gate_t88b_s1/s2/s3` **P**；功能全量 145/145 **P**。等级：行为 **P**；门级全矩阵/SDF **F**。
5. **追问**  
   - 为何自研 MAC？→ 与 BAG/IC/RM 同 TB 闭环；口是 GMII A/B（答辩要点 Q2）。  
   - 坏 FCS 怎么办？→ `desc_vld` 不发；`crc_err`/`drop_reason=01`（T88 步 4）。  
   - IF_MODE=0 与 2？→ 0 带 ready 包络；2 为公开 GMII 连续 DV；时延数字勿跨模式拼。

## 4. VL 哈希查表（`rx_vl_lookup`）

1. **一句话**：把 16 bit VLID 映射到最多 4096 个 RX 表项索引，流水双表 4-way，不是线性扫表。
2. **原理**：`HASH_BUCKETS=2048`；流水 `IDLE→HASH_ADD→HASH_MUL→RAM_READ→COMPARE→OUTPUT`。两表两路：`table0way0/1`、`table1way1`。例：T12c `lookups=100000` 连续命中对账；命中 `out_hit`、给出 `idx`。
3. **代码位置**：`rtl/rx/rx_vl_lookup.v`  
   - `HASH_BUCKETS` **L14**；状态枚举 **L42–43**  
   - BRAM 读写 `always` **L107**；主 FSM `always` **L136**；`case (state)` **L152**；`out_hit` **L174**；`out_vld` **L177**  
   - 关键信号：`in_vld`、`out_hit`、`out_vld`、`hash0`/`hash1`（**L67–70**）
4. **对应测试**：T12c/r/s/h/f；规模 T35p（4096 RX 覆盖）；T08f 记分板。结果：`t35p_pass` **P**；全量 145 含 T12 族 **P**。等级：**P**（表/查找）；「4096 路同时收」**F**。
5. **追问**  
   - 为什么不是 CAM/线性？→ 4096 项用哈希+4-way，面积与查找拍数固定（设计文档查表章）。  
   - 冲突怎么办？→ 双独立哈希种子；golden `sw/golden/hash_seed.py` 位一致（头注释 L60）。  
   - 和 T90 什么关系？→ T90 证 128 TX 吞吐；4096 覆盖看 T35p，勿混成「同时收」。

## 5. IC 完整性检查（`rx_ic`）

1. **一句话**：按 VL 维护上一成功 SN（PSN），只接受期望 SN / 丢一帧 / 复位规则内的帧；拒绝不改 PSN。
2. **原理**：FSM `ST_IDLE→CMP→WRITE→OUT`；`exp1=psn+1`（255→1），`exp2` 允许丢一。例：PSN=10 时 SN=11→`R_OK`；SN=12→`R_LOST_ONE`；SN=13→拒。`out_accept` 仅在接受路径写回。
3. **代码位置**：`rtl/rx/rx_ic.v`  
   - 状态 **L36**；PSN RAM `always` **L61–64**；组合判决 `always @*` **L76–95**  
   - 时序 FSM **L97**；`case (state)` **L117**；`accept_q`/`out_accept` **L130–135**  
   - 关键信号：`out_accept`、`out_reason`、`psn_q`、`sn_q`、`ic_first_any`
4. **对应测试**：T09/T09s/T09p；顶层 T08e/eg；T88 步 4 重放拒绝。结果：`t09_*` 与模型一致 **P**。等级：**P**（剧本范围）；全错误笛卡尔 **F**。
5. **追问**  
   - IC 在 RM 前还是后？→ **IC→RM**（fig1 / 设计文档；CTL bit2/bit3）。  
   - SN=0？→ 接受并 `R_RESET`（L80–82），语义为复位标记。  
   - 拒绝改不改表？→ 不改；`commit_we` 仅 `accept_q`（L56）。

## 6. RM 双网去重（`rx_rm`）

1. **一句话**：A/B 双冗余网上，同 VL 同 SN 在 SkewMax 内的副本只转发一次。
2. **原理**：`Skew = 4 << skewmax_exp`（μs）。`seen && sn==last_sn && |Δt|≤Skew` → `drop_dup`；超时同 SN → forward + `out_skew`。另有 8 深 `hist` 防迟到副本。例：skew_exp=0 → Skew=4 μs；两网同 SN 相隔 2 μs → 第二份 `out_fwd=0`。
3. **代码位置**：`rtl/rx/rx_rm.v`  
   - 判决注释 **L11–29**；状态 **L67**；主 FSM **L118**；`case` **L127**  
   - `skew_q <= 24'd4 << in_skew_exp` **L133**；`fwd_q` **L138**；`out_fwd`/`out_skew` **L146**  
   - 关键信号：`out_fwd`、`out_skew`、`in_skew_exp`、`late_dup`
4. **对应测试**：T10/T10g；T88 步 2/3/8。结果：fwd/dup/skew 与模型一致 **P**（`t10_*`）。等级：**P**；babbling/任意迟到历史 **F**。
5. **追问**  
   - 断 A 只留 B？→ T88 步 3：单侧仍可交付（演示场）。  
   - SkewMax 上限？→ 注释：上限约 131 ms（L16）；本 TB 用配置的 exp。  
   - 去重后吞吐？→ T90 RX 去重 **673.304 Mbps**（报告 §5.3）**P**。

## 7. 块池（`rx_block_pool`）

1. **一句话**：管理 RX PMEM 有限块（默认 16 bit `free_map`），给 A/B 入站与重组/管道归还，防泄漏与耗尽无计数。
2. **原理**：复位 `free_map=16'hFFC0`（块 6…15 空闲；0…5 保留语义依顶层）。`alloc_a/b` 组合挑最低空闲 bit；多路 `free_*` 或回。例：两网同时到 → 同拍可各分配一 blk；耗尽则 `exhaust_cnt++` 且 `valid_a=0`。
3. **代码位置**：`rtl/rx/rx_block_pool.v`  
   - 组合分配 `always @*` **L92–111**；时序更新 **L113–124**  
   - `free_map` 复位 **L115**；`alloc_chain` 路径 **L44–68**（分片链）  
   - 关键信号：`alloc_a`/`blk_a`、`free_map`、`exhaust_cnt`、`borrow_cnt`
4. **对应测试**：T08* 入站分配；T60/T65 重组所有权；T66/T67 主机争用。结果：纳入全量 145 **P**（各 TB）。等级：**P**（标题范围）；「池永不耗尽」无专用长稳 **F**（T18 8h 禁宣）。
5. **追问**  
   - 为什么有 borrow？→ 高编号块给溢出/特殊路径计数（L123–124）。  
   - 释放谁负责？→ MAC 坏帧 `blk_release`、管道、重组、port_buf、spill 多源汇入。  
   - 和分片关系？→ `alloc_chain_count` 一次申多块（L56–68）。

## 9. 615A / TFTP（`a615a_tftp` 等）

1. **一句话**：硬件 TFTP 子集支撑 615A 风格加/卸载：WRQ 写加载区、RRQ 读 STATUS/UPLOAD，非完整航电装载认证。
2. **原理**：WRQ(2) 白名单+octet→ACK(0)；DATA 512 B 块写 + CRC32；RRQ STATUS→32 B；UPLOAD 回镜像。例：T88 步 6 **520 B** 写读回；块号重复只 ACK 不计写（`dup_cnt`）。

   - 关键信号：`resp_vld`/`resp_len`、`loaded_ok`、`bytes_rcvd`、`crc32_val`、`sess`
4. **对应测试**：T16/T16u；T32/T37/T40/T45/T49；T88 步 6；T43。结果：子集 TB **P**。等级：**P（子集）**；「完整 615A/665 认证 / 对端真装载设备」**F**。

## 10. RTC（`rtc_sync`）

1. **一句话**：用外部 PPS（及可选同步报文）校正 `offset`，输出 `rtc_time_us`，超时置 `sync_loss`。
2. **原理**：`rtc_time_us = rtc_free_us + offset + freq_bias`。|err|>TH_JUMP 跳变，否则平滑；连续 `LOCK_N=3` 次 |err|≤1 → `locked`。例：仅 PPS 时默认 `SYNC_TIMEOUT=2_500_000` μs（约丢 2 个 1 Hz PPS 后失步）；T88 步 7：PPS 后 `sync_loss` 清、时间前进。
3. **代码位置**：`rtl/mgmt/rtc_sync.v`  
   - 头注释 **L5–20**；`rtc_time_us` 赋值 **L105**；`pps_event` **L109**  
   - 主 `always` **L145**；`sync_loss`/`locked` 更新 **L218–248**  
   - 关键信号：`pps_in`、`sync_loss`、`locked`、`rtc_time_us`、`last_err_us`
4. **对应测试**：T16a（漂移精度）/ T16r / T16b / T39 / T85；T88 步 7。结果：`t16a_pass` 等 **P**（各 TB）。等级：**P**（μs 分辨率）；亚微秒/PPS CDC 签核 **F**（头注释 L19–20）。
5. **追问**  
   - 时基谁产生？→ `timebase` 的 `rtc_free_us`；本模块只维护 offset。  
   - 为何曾误报失步？→ 旧 `SYNC_TIMEOUT=4000`≪1 s（注释 L14–16）。  
   - FLL？→ `FREQ_LOCK_EN` 且 `US_PER_SEC≥100000` 才开（L70）。

## 11. 分片与重组

1. **一句话**：TX 大消息按 IPv4 片发出；RX 按 ident/地址/VL 收齐 MF=0 且无空洞后交付（默认顶层重组旁路时可关）。
2. **原理**：TX：`tx_message_store` 按剩余长度切 ≤1472 B 应用载荷；`tx_fragment_launch` FSM `IDLE→SNAPSHOT→LAUNCH→BUILD` 取 SN 再组片。RX：`rx_reassembly` 槽位覆盖区间，MF=0 且 `[0,end)` 盖全才 `out_vld`。例：应用 3000 B → 至少 3 片（1472+1472+余量）；末片 `MF=0`。
3. **代码位置**  
   - `rtl/tx/tx_fragment_launch.v`：状态 **L34**；`always`/`case` **L61–69**；`snap_req` **L47**  
   - `rtl/tx/tx_fragment_frame_builder.v`、`tx_message_store.v`、`ipv4_fragment_plan.v`  
   - `rtl/rx/rx_reassembly.v`：参数 `MAX_FRAGS=16` **L29**；主 `always` **L441**；`in_mf` **L153**；覆盖/完成逻辑同文件后部  
   - `rtl/rx/rx_reassembly_chain.v`（链拷贝，条件例化）  
   - 关键信号：`last_fragment`、`fragment_offset`、`out_vld`/`out_drop`、`slot_vld`
4. **对应测试**：T51/T52/T80（TX 计划/头/builder）；T60/T65/T66/T67/T79（RX 重组）。结果：纳入全量 145 **P**。等级：**P**（已跑 TB）；默认配置下「线上必重组」勿夸大——fig1 注：默认 `ctl_r[7]=0` 时 RM 后可直连解析（**I** 说清配置）。
5. **追问**

## 数据通路白板画法

**TX（一条线，左→右）**

```
主机前门(AFDX_top 译码)
  → tx_port_buf
  → tx_vl_scheduler（BAG）
  → tx_frame_builder（← tx_sn_gen）
  → tx_rm
  → mac_tx_if ×2（← tx_pace）
  → GMII A / GMII B
```

（大消息可选：`tx_message_store` → `tx_fragment_launch` → `tx_fragment_frame_builder`，默认链参数关闭时不画进主链。）

**RX（一条线，左→右）**

```
GMII A/B
  → gmii_rx_strip ×2
  → mac_rx_if ×2
  → rx_pmem_queue → 顶层串行（A 优先）
  → rx_vl_lookup → rx_flt
  → rx_ic → rx_rm
  → rx_ip_udp_parse
  →（可选 rx_reassembly）
  → rx_port_buf → 主机
       ↘ mgmt_sap_rx → snmp_lite / a615a_tftp / rtc_sync
```

## 答辩要点 7 题标准答案（每题 ≤3 句）

1. **仿真为什么是 125 MHz？做没做时序签核？**  
   赛题要求综合后仿真，未要求时序签核。仿真时钟按 GMII 字节节拍取 125 MHz。本作品不做布局布线后时序收敛宣称。

2. **为什么自研 MAC，没用 eLinx IP？**  
   交付是 ES 协议行为 + 自建 TB；物理口是组委会确认的 GMII A/B。自研 `mac_tx_if`/`mac_rx_if` 便于与 BAG/IC/RM 同一仿真闭环；eLinx 是综合入口，不强制绑其以太网 IP。

3. **128 TX / 4096 RX 怎么验证？**  
   表与查找：T12* / T35p（`t35p_pass`）。128 TX 同时活动吞吐：T90 **P**（TX≈679 Mbps，RX 去重≈673 Mbps）。不是「4096 路同时收」，也不是任意 BAG 均 ≥100 Mbps。

4. **「2 ms」的起止点？**  
   官方字面单帧 GMII SFD→SFD ≤2 ms：单 ES 回环无网络段 → **I**，不宣称已 P。本工程 P：T89 commit→TX SFD / RX SFD→host / 二者之和（例 es_total **5976 ns**）。不以「官方 2 ms 已 P」表述。

5. **为什么在 1G GMII 上跑 100 Mbps AFDX？**  
   口用 1G GMII 节拍便于与常见 MAC/FPGA 模型对齐。业务侧用 BAG+份额约束聚合带宽（T05b/c、T27）。接口速率 ≠ 已声明的 VL 预算；满配吞吐见 T90。

6. **预言机和 RTL 同一批人写，怎么保证可信？**  
   外置 Python 黄金、双仿真器 145/145 一致（`dual_sim_match`）、C3 变异分列、覆盖率双口径披露。仍承认：不是认证实验室；PASS 只覆盖该 TB 标题。BAG BMC 维持 **F**。

7. **615A、SNMP 的范围？**  
   SNMP v1 lite + TFTP/615A 加卸载相关子集；证据 T88 步 5–6、T15/T16/T43 等。不含完整 ARINC 615A/665 认证，也不含对端真装载设备闭环。
