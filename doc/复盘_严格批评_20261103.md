## 0. 总判（先结论）

本项目在 **RTL 功能仿真与冻结打包** 上做出了可核对的成果（140→150 全量、双仿真器、T88b 门级切片、REPLAY）。  
系统性失误不在「不会写模块」，而在两条有直接出处的长期错位，外加一条观察：

1. **赛题点名的工具路径（eLinx 编译及仿真 / 综合后仿真）被后置**（10-20 计划仍写「从未跑过」；10-31 灰按钮 I/F）；  
2. **目标器件面积收敛过晚**（10-03 已有 LE 压缩备份，11 月初才在 EQ6HL130 上压到限内）；  
3. **观察（非并列主因）**：后期大量「勿拼版本 / 冻结锚点」纪律，与多冻结号并存（`51f117d` / `fced41c` / `1b54dad`）同时出现——说明版本管理曾是痛点，但「前期一定混用过对外数字」无单条造假实证，不升格为已证实指控。

责任主体是项目主导决策（验证优先级与里程碑绑定），不是单日对话。

## 2. 全流程错误清单（按发生先后 / 影响）

### P1 · 调研期未锁定「eLinx 仿真」最小路径（贯穿全程的主因）

- **要求（当时已知）**：选题指南写明全部通过 eLinx 编译及仿真；答疑「综合后仿真即可」（`提分执行计划_20261020.md` §0.1）。  
- **事实**：至 10-20 计划仍记「当前源码综合后仿真 = F，从未跑过」；10-31 才认真打到灰按钮停条件。  
- **过程选择**：优先堆 RTL 用例矩阵与 Questa/SE 全绿；eLinx 多用于综合 cells/GUI 行为旁证（如 10-23 T88b GUI transcript）。  
- **与「不上板」的关系**：笔记 `比赛不要求实际上板.md` 只免除板测；**不能**推导为免除 eLinx 仿真。将二者混用，是口径错误。  
- **影响**：交卷时 C139.4 /「eLinx 调起综合后仿真」只能标 I/F；旁证再完整也不能升格（H7）。  
- **责任**：项目优先级排序——把赛题点名路径放在功能矩阵之后。  
- **改则**：开题第一周必须产出「eLinx→ModelSim 最小 Transcript」或书面 I/F；否则禁止宣称工具链闭环。  
- **状态**：未在交卷前闭合。

### P2 · 10-30 与 10-31 两份状态并置（收口范围不含 eLinx 调起仿真）

- **证据（并列原文，不加额外定性）**：  
  - 2026-10-30：`交接_顾问对话_20261030.md` §0 写「最终冻结已完成且全部通过」「AI 侧技术工作已基本结束」。  
  - 2026-10-31：`状态确认_提交占坑_20261031.md` §0/§2 写「eLinx『综合后仿真』未通（I/F）」。  
- **可核对事实**：10-30 所指「全部通过」在同文档证据表内对应 RTL 全量、T88b、封装综合、RAR/REPLAY；**未**把「eLinx 调起综合后仿真」列进该表为 P。  
- **影响**：交卷叙事易让人以为工具链已闭环，而点名路径次日仍为 I/F。  
- **责任**：冻结门禁未包含指南要求的 eLinx 仿真路径。  
- **改则**：冻结门禁表必须含「赛题点名工具路径」一行；旁证不得替门禁。  

### P3 · 面积/器件危机后置（10-03 已备份，11 月才真压到 EQ6HL130）

- **证据**：`045044f`「snapshot before LE compression」；10-31 GUI 综合 LE **217245**；`ab_area` 2H 才进 LE≤136000 且 CLB≤13600。  
- **事实**：早知要压资源，但满配功能与提分主线长期占档；目标器件装不下拖到交卷前隔离树突击。  
- **影响**：FN512 等刀在截止窗口引入契约破坏（见 P4）；面积达标与回归合入冲突。  
- **责任**：未把「目标器件可综合且可仿真」与功能冻结绑成同一里程碑。  
- **改则**：选定器件后，**同里程碑**要有：综合进限 + 最小仿真路径；禁止「功能全绿后再说面积」。  

### P4 · 改接口不先验契约测试（FN512 与 T49/T58 失败同机制）

- **证据**：`out/ab_area_20261102/step2f_fn512_NOTE.md`（2048→512）；`logs_2H_stop_20261103_165025/T49_console.txt`（`Connection width does not match` + `A RRQ filename bytes`）；`tb_t49_tftp_client.v` 将文件名写入 `filename[2047-:8]`；隔离 DUT 端口曾为 `[511:0]`。  
- **机制陈述（非口头归因）**：TB 按 2048 MSB 打包，DUT 只接收低 512 位截断连线时看不到文件名字节 → 与日志中的 filename 检查失败一致。  
- **过程事实**：面积 GUI 数字先冻结，契约单元测后置；2H 回归账本将 T49/T58 记为相对旧 13F 的**新增 FAIL**。  
- **影响**：隔离树按原判据不能合入主树。  
- **责任**：刀后验证顺序错误（先 GUI 数字，后单元契约）。  
- **改则**：端口/位宽变更 = 同日跑直接消费者 TB。  
- **状态**：隔离树端口适配后 T49/T58 单元 PASS；是否合入取决于其后全量账本。  

### P5 · 多冻结锚点并存与「勿拼」纪律（观察项）

- **不可证实（不指控）**：无单条入库证据证明「对外已提交材料把两版数字拼成一句假全绿」。  
- **影响**：若答辩口误混锚点，听众无法复核。
