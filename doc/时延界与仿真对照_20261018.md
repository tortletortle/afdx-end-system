## 1. Nbw 口径分歧（先查再算，未改 TB）

| 来源 | 说法 |
|---|---|
| L158 / 摘录 `doc/ARINC664P7_条款摘录_20260928.md` §2.1 | `Nbw` = **介质带宽**（bit/s），不是有效载荷吞吐 |
| `tb_t13w_worst.v` 头注释 | 第一式写死 `/100 Mbps`；`J = 40+(3*1538+3*376)*0.08 = 499.36 μs` |
| 同文件注释 IF_MODE=1 | 字节背靠背，**约 1 Gbps**，排队短一个数量级；**仍打印** `arinc_bound=499360ns`（100 Mbps 式） |
| 项目 IF_MODE（`doc/接口契约.md`） | 0：旧 100 Mbps 节拍；1：连续字节约 1 Gbps；2：PHY GMII，接口容量 1 Gbps，**有效载荷**另测 ≥100 Mbps |

**结论（写入工具，不改 TB）**：

1. 规范合规抖动式的 `Nbw` 指介质速率；传统百兆 AFDX 取 **100 Mbps**。
2. TB 在 IF_MODE=1/2 仿真节拍变快时，**故意**仍用 100 Mbps 第一式作 `arinc_bound`——这是配置/规范口径，不是「仿真线速」。
3. 计算器对 **100 Mbps** 与 **1 Gbps** 两种 `Nbw` **都算**；`IF_MODE` 只选主口径标签（0/2→主报 100 Mbps；1→主报 1 Gbps）。
4. 不得把「IF_MODE=1 实测排队短」写成「规范允许把 Nbw 改成 1 Gbps」。

## 2. 模型假设（与 RTL/TB 只读对齐）

| 假设 | 依据 |
|---|---|
| Lmax = DA 起算含 FCS 的 MAC 帧长 | `doc/接口契约.md`；T13w 用 1518 / 356；T82 用 1518 |
| 抖动第一式 `40+Σ(20+Lmax)·8/Nbw`，再 `min(.,500)` | L158 §3.2.4.3；T13w / 尺子 §2 |
| 争用集合 = **同一物理网口**上的 VL，不是主机 port | T05b 第一式对 32 VL 求和 → 866.88 μs（尺子） |
| BAG 以线上 MAC 帧起始周期计；16 拍扫一轮；`sch_ack` 2 拍 | `rtl/tx/tx_vl_scheduler.v` 头注释 |
| 合法 BAG 表 1…128 ms（2^k ms） | `tb_s3_bag_legal.v`；T05b 的 828 μs 是**压力档**，不是合法功率档 |
| 忙期排队界 = 同网口全部 Lmax 串行化时间 | 工具 `busy_period.serialize_*` |
| 多片：`(n−1)·BAG + 首片等待 + J + 末片串行化`；首片等待=`max(BAG, 忙期串行化)` | 任务书；初版仅用串行化会低估（见 §4 模型修正）；T82 对照后升 **P** |

## 4. 多片消息（8192 B）— 单列

**口径**：T82 量 `commit_call_to_last_A_ns`（主机 commit 调用 → 网 A 末字节）。含主机等待与 BAG 相位，**不是**赛方「GMII ≤2 ms」官方负载/起止（该口径仍 OPEN，见 `doc/AFDX项目应用追踪.md`）。本表只判「实测 ≤ 本计算器工程界」。

**配置**（`tb_t82_tx8k_gmii.v`）：单 VL、Lmax=1518、合法 BAG=1000 μs、默认顶层 IF_MODE=2；`n_frags=ceil(8192/1472)=6`；末片应用 832 B → Lmax=879。

**计算器界**（`--preset t82 --if-mode 2`）：

```text
bound = (6−1)·1000 + max(1000, 121.44) + 163.04 + 70.32
      = 5000 + 1000 + 163.04 + 70.32
      = 6233.360 μs
```

| 场景（量） | 计算器界 | 实测（来源） | 实测≤界？ | 紧度 | 等级 |
|---|---|---|---|---|---|
| T82 8192B `commit_call_to_last_A`（两轮） | **6233.360 μs** | index=14：**6063.448 μs**；index=15：**6161.736 μs**（`T82_console.txt`；追踪亦记 6.063448 / 6.161736 ms） | **是**（取最差 6161.736） | 余量 71.624 μs；占用 98.85% | **P** |

**模型修正（不判 RTL 穿帮）**：初版把「首片等待」等同忙期 Lmax 串行化 → 界≈5354.8 μs &lt; 6161.736 μs。T82 单帧同量已见 ~1 ms 档（BAG 相位），故改为 `首片等待 = max(BAG, 忙期串行化)`。修正后界盖住实测；**未**改 RTL/TB。

**禁止**：把 6.16 ms 写成「满足 2 ms」；把本项升格为官方 2 ms 关闭。
