# 工作规范 · 里程碑门禁（G1–G5）

> 来源：全流程复盘 `doc/复盘_严格批评_20261103.md`；顾问裁定 **D**（5 条门禁 + 一页三张勾选表）。  
> **与硬约束关系**：本规范补 H1–H12 **未覆盖的时序/里程碑门禁**。与 H 冲突时 **以 H 为准**。经验笔记 E1–E16 是经验，**不作门禁**（已升为 G 的在笔记侧可注「已升 Gx」）。  
> 目的：下次避免「点名工具路径后置」「面积过晚」「契约刀无 TB」「冻结不含点名路径」「冻结后想降标准」。

---

## 0. 一句话

**功能可以后堆，赛题点名的工具链仿真、器件进限、契约测试不能后置；冻结只有一个锚点；冻结后不许降标准。**

---

## 1. 门禁正文（G1–G5）

### G1 · Week0 点名工具链（开题周）

- **做什么**：赛题点名的厂商工具链（本赛例如 eLinx「编译及仿真」/综合后仿真）在 **Week0**（选题/开题日起 7 天内，落盘前写死起点日）跑通 **最小可复现路径**，或书面标 **I/F** 并进尺子。  
- **门禁证据**：可复现日志/Transcript + 操作步骤路径。  
- **停条件**：未跑通且未书面 I/F → **禁止进入 RTL 主体功能堆量**。  
- **对齐**：落实 H11（资料齐→标准→再实现）；不替代 H6（灰按钮仍停猜）。  
- **禁推演**：「不上板」≠「可免点名工具链仿真」。

### G2 · 器件选定周：资源进限同周关门

- **做什么**：选定目标器件的那一周，写入 LE/CLB（或赛题等价上限），并出 **第一版** 综合/资源报告。  
- **门禁证据**：器件型号 + 上限表 + 报告路径。  
- **停条件**：超限或缺失报告 → **禁止新增功能模块**；只允许减资源或换方案。  
- **对齐**：H4（面积未重测不得写已变小）。

### G3 · 契约定稿日 = TB 同日

- **做什么**：模块对外契约（位宽、包序、MSB/LSB、文件名长度等）定稿 **当天**，对应消费者 TB 入库并跑通。  
- **门禁证据**：契约说明 + TB 名 + 当日 PASS 日志。  
- **停条件**：无 TB 的契约 **不算定稿**；下游不得当稳定接口引用；**不得**据此做面积冻结。  
- **对齐**：H2（无 T 最多 I）；禁止用「先综合看数字再补测」绕过。

### G4 · 冻结必须含点名路径 + 唯一锚点

- **做什么**：称「冻结 / 技术收口 / 可交」时，必要条件包括：  
  1. 赛题点名工具路径的通过记录，或尺子上的 **I/F**；  
  2. **唯一**冻结锚点（一个 commit / 一个冻结目录）；观察项另表，不作锚点。  
- **门禁证据**：冻结清单勾选 + 锚点 hash + 点名路径记录（或 I/F 文件）。  
- **停条件**：缺点名路径记录 → **不准叫冻结**，只可叫「功能旁证阶段」。  
- **对齐**：H7（旁证禁升）；H9（不把 I 写成 P）。

### G5 · 冻结后禁止降标准

- **做什么**：冻结后不得删/弱化 manifest 用例、不得改预言机迁就 RTL、不得把旁证升主证据。要改标准 → **解冻** → 回到 G4 重冻。  
- **门禁证据**：交卷前标准与冻结版 diff 为空，或解冻记录。  
- **停条件**：出现「删失败测试就能交」类动议 → 直接否决（同 H3 精神）。  
- **对齐**：H3。

## 4. 使用方式

1. 新开 FPGA/赛题项目：复制本页 + 三张表到项目 `doc/`，填 Week0 起点。  
2. Cursor always 仍只挂 H 编号；本规范按需打开，不塞进 always 全文。  
3. 顾问/执行分工不变：触达停条件 → 标 I/F 或解冻，不猜菜单、不删测。
