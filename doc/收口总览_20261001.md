## 四、文档归档和修改原则

- **现行入口**：本页 → 阶段一交付说明 → 比赛核查清单 → 当前测试报告 A 节 → 总体设计书现行章节；技术结论须回到状态 JSON / 原始日志。`doc/README.md` 负责文档地图而不是又写一份规格。
- **历史但必须保留**：Continue12 56/56、Step3 62/62、9/23～9/28 进度、旧 Fit、旧试包、失败输出与 `before/`/`candidate/`。写“何时/何源”，不改旧数凑新数。
- **文献/赛题/证据分开**：`文献/README.md` 与 `AFDX文献目录.md` 管本地文件和 L 编号；论文不等于合规证据；`competition_case/` 是另一选题。
- **不在文档收口中擅自执行工程命令**：旧 `sim/run_regress.ps1` 可能按进程名结束他人仿真并覆盖固定目录；人工 Fit 可能耗时且有机器资源风险。每项工程动作须先确认运行窗口、输入和副作用，使用新证据目录与 tag。
