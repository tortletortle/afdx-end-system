### 6. docx / PDF 生成规则

1. **docx 在冻结 worktree 里生成**（`git worktree add --detach <路径> <冻结 commit>`），保证输入都来自已提交的文件。官方模板在 `doc/官方模板/报告模板.docx`，生成器默认读它（不进提交包）。
   ```
   python tools/gen_app_top_fig.py
   python tools/gen_submit_layout_figs.py        # 先把 METRICS 常量改成新 metrics 路径
   python tools/build_official_tech_report.py --metrics <新 metrics.json>
   python tools/render_doc_metrics.py --metrics <新 metrics.json>
   ```
   用 `PYTHONDONTWRITEBYTECODE=1`，输出写到 worktree 之外或已被忽略的目录，避免 worktree 变脏；生成完用 `git worktree remove <路径>` 清理（不用递归强删）。
2. **PDF**：生成器在 worktree 内用 Word COM 导出。若失败（`WARN pdf not exported`），**不要重新生成 docx**：在主工作树对**同一个 docx 文件**导出 PDF，或用 Word「另存为 PDF」。
3. **记录哈希**：生成后立即对最终的 docx 和 pdf 各算一次 sha256，写进 `out/<冻结目录>/STATUS.md` 和交付表备注：
   ```
   Get-FileHash <docx>, <pdf> -Algorithm SHA256
   ```
   PDF 如果是在主工作树另导出的，同时记录它所对应的 docx 哈希，二者必须是同一个 docx。之后进 RAR 的 docx/pdf 必须与记录一致，打包后再核对一次。
4. 生成完成后核对：交付表字数全 OK、`residue` 全 0、`identity` 全 0；docx 里搜不到 `MISSING`、`图位待补`。

T93 的 `t93_gmii_sfd.csv` / `t93_vl_gap.csv` 由 `run_regress.ps1` 拷入该测试的输出目录，全量 run 里应存在。
