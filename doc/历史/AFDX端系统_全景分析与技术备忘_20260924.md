### 2.2 发送端（TX）关键设计与时序流水
- **无首部寄存器堆（Zero-Header Buffer）**：首部 42 字节不落寄存器堆，而是采用字段寄存器经 42 选 1 组合 Mux 按发送偏移直接输出，节省约 1,000 个 FF。
- **两遍扫描重叠（Overlapped 2-Pass）**：
  - Pass 1：走 PMEM 读口 A，以 4 字节/拍（32 位宽）累加 UDP 反码和（最大 1471 字节载荷只需 ⌈1471/4⌉ = 368 拍）。
  - Pass 2：同时从首部字节 0 启动发送，UDP 校验和字段在字节偏移 40 处才需要，线速下 40 字节 × 10 拍 = 400 拍 > 368 拍。因此 Pass 2 绝无需等待 Pass 1，实现零空拍线速流式发送。
- **SN 生成与回绕**：采用 `snap_req`（快照预留）与 `commit`（线上末字节确认发毕反馈）两阶段机制，确保异常帧不浪费 SN。
- **BAG 调度与时钟回绕**：维护 24-bit μs 时基（模 2^24），年龄计算 `age = (tb_us - next_tx) mod 2^24`，最高位为 0 判定到期，128 拍轮询一圈。以线上首字节 `frame_start` 为下次 BAG 锚点。

### 2.3 接收端（RX）关键设计与前段成果
- **流式首部抓取与就地校验（O-04/O-05）**：`mac_rx_if` 在接收字节流时，实时抓取前 42 字节首部，并在移位寄存器中保留末尾 5 字节（1B SN + 4B FCS）。同时并行展开 8 级 XOR CRC32 和 IP/UDP 反码累加。
- **错误帧就地丢弃**：坏 FCS、非法首部或截断帧在末尾字节判定失败时，直接原地释放 PMEM 块，绝不生成有效描述符（`desc_vld`），彻底阻断坏帧污染后级状态 RAM。
- **4096 VL 布谷鸟哈希查表（O-13）**：2 表 × 2048 桶 × 2 way，双 bank 并行读取，固定 2 拍返回，负载率 50%，离线通过增广路径解决冲突。
- **FLT 语义过滤（v0.5.13）**：四类判定（UNCONF 未配置、NET 网络模式不符、VLID 表项不匹配、LMAX 超长），已接入顶层并通过 T08d/T08dg 双模式验证。

### 2.4 主机前门与 PMEM 单写口争用仲裁（HOST-01 契约）
- PMEM 为 1 写 2 读。写口为双网 RX 写入与主机写入共享。
- **契约规则**：
  1. RX 写入绝对优先；
  2. 若主机与 RX 同拍写冲突，顶层锁存主机单笔请求（`host_pmem_pending`）；
  3. 主机必须等待 `host_ack`，在待决期间不接纳新事务；
  4. 只有在主机数据真正写入 BRAM 那一拍才拉高 `host_ack`（延迟 ACK），绝不过早 ACK 或丢失写入；
  5. 复位同步取消待决请求。已通过 T08c/cg 40 笔严苛冲突与 3/3 故障注入验证。

## 3. AFDX 规范标准与帧格式线序（O-01/O-02）

以太网帧总长（DMAC 起算含 FCS）范围为 64 ~ 1518 字节：
$$\text{Frame Length} = 14(\text{ETH}) + 20(\text{IPv4}) + 8(\text{UDP}) + L(\text{Payload}) + P(\text{Pad}) + 1(\text{SN}) + 4(\text{FCS})$$

| 字段 | 长度 | 范围 / 偏移 | 规范关键约定与设计决策 |
|---|---|---|---|
| **DMAC** | 6 B | 0 ~ 5 | `03-00-00-00-VLID[15:0]`，bit0=1(组播), bit1=1(本地管理)；硬件仅比较前 4 字节，后 2 字节直接作为 VLID 输入查表 |
| **SMAC** | 6 B | 6 ~ 11 | `02-00-00-UDI[15:0]-{IFID[2:0], 5'b0}`；A 网末字节固定为 `0x20`，B 网末字节固定为 `0x40` |
| **EtherType** | 2 B | 12 ~ 13 | 固定为 `0x0800` (IPv4)；其余类型直接拒绝 |
| **IPv4 Header** | 20 B | 14 ~ 33 | 固定无选项；**Total Length = 28 + L**（**不含 Pad 与 SN！**）；反码求和取反 |
| **UDP Header** | 8 B | 34 ~ 41 | Src Port 来自配置（49152+port）；**Length = 8 + L**（**不含 Pad 与 SN！**）；覆盖伪首部+载荷 |
| **Payload** | L B | 42 ~ 42+L-1 | 1 ≤ L ≤ 1471 字节；由主机写入 PMEM |
| **Pad** | P B | 42+L ~ 42+L+P-1 | $P = \max(0, 17 - L)$；**位于载荷与 SN 之间，不计入 IP/UDP 长度，不进 UDP 校验和** |
| **SN** | 1 B | FCS 前 1 字节 | 取值 1 ~ 255 循环；位于 `14 + Total Length + P`，必须等于 `len - 5` |
| **FCS** | 4 B | 帧末 4 字节 | IEEE 802.3 CRC32，多项式 `0xEDB88320`；**低字节先发 (LSB first)**，好帧 zlib 余数 `0x2144DF1C` |

## 4. 关键算法与数学公式

### 4.1 布谷鸟哈希算法（mix_bucket）
硬件与 Python 黄金模型完全一致的混淆位运算（加法混淆种子，打破同槽相关性）：
```verilog
function [10:0] mix_bucket;
  input [15:0] vlid, seed;
  input table_id;
  reg [15:0] x;
  begin
    x = vlid + seed + (table_id ? 16'h1F5B : 16'h9E37);
    x = x ^ (x >> 7);
    x = x * (table_id ? 16'h45D9 : 16'h9E37);
    x = x ^ (x >> 9);
    mix_bucket = x & (HASH_BUCKETS - 1); // 2048 桶
  end
endfunction
```

### 4.2 IC 完整性检查判决状态机（A664P7 §5.2.2）
```verilog
if (sn == 0) accept = 1, new_psn = 0, reason = R_RESET; // 复位判决
else if (psn == 0) begin
  accept = (sn == 1 || ic_first_any);
  new_psn = accept ? sn : 0;
  reason = (sn == 1) ? R_OK : (ic_first_any ? R_FIRST_ANY : R_FIRST_FAIL);
end else begin
  exp1 = (psn == 255) ? 1 : psn + 1;
  exp2 = (psn >= 254) ? psn - 253 : psn + 2;
  if (sn == exp1) accept = 1, new_psn = sn, reason = R_OK;
  else if (sn == exp2) accept = 1, new_psn = sn, reason = R_LOST_ONE; // 容错丢失1帧
  else accept = 0, new_psn = psn, reason = R_OUT_OF_ORDER; // 乱序/丢≥2帧
end
```

### 4.3 BAG 带宽定点预算与 Q20 公式
单帧线上占用时间：$T(Lmax) = (Lmax + 20) \times 80\text{ ns}$（含 7B Preamble + 1B SFD + 12B IFG = 20B）。  
每条 VL 的带宽份额（定点 Q20，以 $2^{20} = 1,048,576$ 为 100 Mbps）：
$$\text{share\_q20}_j = \left\lceil \frac{(Lmax_j + 20) \times 80\text{ ns}}{BAG_j} \times 2^{20} \right\rceil$$
硬件累加求和：$\text{CFG\_SUM} = \sum \text{share\_q20}_j$。若 $\text{CFG\_SUM} > 2^{20}$，置位 `ERR.BAG_OVF` 并拒绝开流。

## 8. 核心工程风险与攻坚路线图（给施工智能体的建议）

### 8.1 四大高危风险
1. **Git 严重脱节（最高危）**：工作区共有 178 个未提交改动，Git 停滞在 T03 历史提交。**必须立即执行 `git add .` 并创建基线 commit**。
2. **RX 后半链路断链（关键阻塞）**：通过 FLT 的好帧未送往 IC/RM/Port，主机无法读回接收数据，闭环验证被阻断。
3. **T05b 启动同相抖动（架构缺陷）**：当前调度器配置时统一初始化 `next_tx` 为当前时间，32 VL 同相启动将引发 31 × 25.84 = 801.04 μs 排队抖动，超过 A664P7 的 500 μs 上限。需增加 `phase_offset`。
4. **全芯片 125 MHz STA 缺位**：仅有单模块 BRAM 冒烟，缺少全芯片 80 个 BRAM 块下的 125 MHz 时序收敛分析。

### 8.2 推荐攻坚路线（4 步走）
- **第 1 步**：清理根目录 `NUL` 异常文件，提交 Git 基线封桩。

- **第 3 步**：编写 `rx_rm.v`（SkewMax 双网去重）与 `rx_port_buf.v`，打通主机 `MSG_RD` 读回，完成 T08 完整版与 T22 全流程闭环。
- **第 4 步**：调度器增加起始相位错开以通过 T05b，展开 SNMP/TFTP/RTC 管理面（P1），输出 eLinx 交付波形与测试报告。
