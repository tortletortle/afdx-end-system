## 1. 工具名称与版本

- **Cursor** 编辑器内的 AI 编程助手（对话代理；具体底层模型以当时会话为准）
- 用途限于：赛题/文献条款梳理、RTL/TB 修改建议与缺陷排查、回归与证据路径调度、文档口径对齐、打包与汇报材料起草
- **不作为**：综合/Fit/STA/网表签核；不替代组委会原文与本队仿真日志

本机实际判决工具（非 AI）：Questa FSE、ModelSim SE-64 2020.4、eLinx 3.0（综合与 GUI 行为仿真）、必要时 Quartus 代理器件流程。结论以各次运行目录中的 CSV/日志/transcript 为准。

## 2. 使用场景

| 场景 | 是否使用 AI | 说明 |
|---|---|---|
| 文献与赛题条款梳理 | 是 | 对照本地文献目录与组委会答疑，不替代原文 |
| RTL / testbench 编写与缺陷修复 | 是 | 含管理面、公开端口回环 TB（如 T88b）等；以仿真 PASS/FAIL 日志验收 |
| 黄金模型 / 向量脚本 | 部分 | Python 模型与向量为人机协作历史产物 |
| 仿真回归执行 | AI 协助调度与核查 | 编译、仿真、记分板判决由本机 Questa / ModelSim / eLinx 执行 |
| eLinx GUI 实操与截图 | 否（人工） | 第三方仿真器路径设置、Run Behavioral Simulation、截图归档由队员完成 |
| 综合、Fit、STA 结论 | 否 | 以工具原始日志为准；未闭合项（如代理 Fmax）标 I，不由 AI 改写成已签核 |
| 本文档与汇报口径 | 是 | 结构与措辞起草；数字须回溯到日志；终稿须人工核对签字 |

## 3. 生成内容占比（估计，供评委知情；以核对栏确认为准）

- **文字**（设计书 / 测试报告 / 先读 / 本声明）：约 30%～50% 经 AI 起草或改写；结论数字均要求能指到 CSV/日志/行号
- **RTL**：核心收发数据通路为项目既有实现；后续管理面、接口修补、TB 路径兼容等有 AI 辅助修改，以对应 T 号仿真为准
- **电路 / FPGA 网表与时序报告**：0% AI 生成（由 eLinx / Quartus 等工具产出）
- **脚本与工程元数据**（回归、冻结、eLinx sources.f / .epr 对齐等）：有 AI 辅助；厂商仿真库未为得到 PASS 而篡改
