### 文献调研与需求追踪

本项目建立了从**文献 → 架构决策 → RTL → 测试**的完整追踪链，入口为
[项目应用追踪](doc/AFDX项目应用追踪.md)（需求主表 `REQ-*` 与架构决策 `D10–D13`）与
[文献目录](doc/AFDX文献目录.md)（稳定 ID `L*`，按证据等级 A/B/C/D 分级登记）。

**文献不是装饰，它改过设计。** 一个可核查的实例——架构决策 **D10「发送起始错相」**：

- **问题**：32 条 VL 同相启动时，末条 VL 的排队下界为 (32−1) × 25.84 = **801.04 μs**，
  超过 500 μs 合规线（解析模型结论，见 `tools/selfcheck_claims.py` C3 项）。
- **依据**：`L001`（Xilinx XAPP1130）、`L064`、`L067`、`L084`。
- **处置**：改为按 VL / BAG 错相提交。
- **证据**：`T05b` / `T05bg` 以 500 μs 为硬判据，两种 IF_MODE 均 PASS。

追踪链示例（D12 双网冗余消除）：
`L077–L080` → 决策 D12（IC 之后做 RM、维护 SkewMax/seen 状态） → `rtl/rx/rx_rm.v` → `T10`/`T22` → `TOP_LEVEL_VERIFIED`。

**使用边界**（与 `doc/AFDX文献工程映射.md` §1 一致）：
文献是设计依据之一，**不是实现证据**；当前状态一律回到 RTL / TB / manifest / 日志 / 综合 / STA 核对。
普通千兆以太网、RGMII、PHY、CDC 类资料只支撑接口与实现方法，**不支撑 AFDX 协议合规**。
标注为 **D 级**的条目仅凭题名登记、正文未解析，**不得据此形成正文结论**。

## 变更约定

1. 改协议/地址/寄存器先核对设计书、`doc/regs.yaml` 与相关生成器；不要手改生成结果掩盖不一致。
2. 修改后跑相应检查；记录**源版本、测试清单、命令、配置、结果和覆盖边界**。
3. 任何 RTL 变更后串行重跑 56 项回归 + lint + 严格文档门，保留失败原件、真实 rc、命令与哈希。
4. **不得以功能仿真 PASS 宣称综合/时序/认证完成。** 功能、综合、时序、覆盖率四类结果分开列示。
